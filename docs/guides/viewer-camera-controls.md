# 网页和相机控制

运行 `./scripts/shortcuts/网页控制.sh` 打开终端菜单，输入快捷字母后回车：

- W：启动网页（重复启动会返回现有地址）
- E：停止网页监视器，机械臂和相机保持各自状态
- I：查看网页地址及后台 PID
- C / X：开启 / 关闭 RGB 和深度采集
- Q：退出菜单，服务保持运行

也可直接使用 `./scripts/shortcuts/网页控制.sh start|stop|status|camera-on|camera-off`。
`./scripts/viewer/启动仿真.sh` 不带参数时启动同一个受管理网页；携带自定义参数时保持前台运行，Ctrl+C 退出。
机械臂控制台新增 W/E/V 网页开/关/状态及 C/X 相机开/关（旧控制台下次启动加载）。
网页按相机显示独立卡片，各自提供采集开关、型号、采集帧率、分辨率和连接状态；序列号、USB 速度和预览参数放在悬停提示中。
默认并排显示 RGB；“显示深度”按钮将同一位置切换为深度，“返回 RGB”切回。
点击任意画面可放大，Esc 或“关闭”返回；放大画面也会随断流清除，避免把旧帧误认为实时数据。
网页采用单屏布局：上方显示模型、两路相机和手柄，下方显示关节/夹爪位置、速度、力矩、紧凑电机反馈和腕部 D435i IMU；末端计算值与控制诊断收在 3D 区域的“数据详情”。
较小窗口压缩间距、说明与图表；宽度小于 1024 像素时整体缩放，以保留完整视图，不产生页面或面板滚动条。

## 多相机配置

每台 RealSense 对应 `configs/local.toml` 中一个 `[cameras.<名称>]`，用 SDK 序列号绑定，不能重复。
`wrist_rgb` 是手眼标定和终端 C/X 的默认通道。录制列表由 `[recording].camera_ids` 显式指定；
双相机使用 `["wrist_rgb", "exterior_rgb"]`，默认配置及旧数据仍支持单腕部相机。配置示例见 `configs/local.example.toml`。
通过 `./run.sh check-camera --serial <序列号>` 检查设备和 RGB 档位；USB 2 连接需要选择可同时采集 RGB、深度的帧率。
`model` 可设为 `D435i` 或 `D435`，服务在打开采集前核对型号。

更改设备列表、序列号或采集档位后需重启相机服务；单纯刷新网页不重新读取运行中服务的配置。
每台相机独立采集、开关和重连，一台断开不会清除另一台的画面。
预览保持约 5 Hz，宽度不超过 640 像素；标题显示采集帧率和分辨率，预览频率放在悬停提示中。短暂轮询延迟保留已解码画面，超过 2 秒断流才提示并清除画面，避免瞬时状态文字闪烁。
RGB 录像采用两台均支持的 1920×1080、30 FPS；深度预览独立使用 640×480、30 FPS，不随 RGB 升分辨率。MP4 压缩发生在主机，不降低相机到主机的 USB 带宽需求。
深度使用 0.2–2 m 固定色标，未对齐 RGB，不作为像素级对应关系。

IPC 的 `monitor` 返回按名称索引的 `cameras`。`monitor`、`frame`、`set_enabled` 可携带 `camera_id`；
省略时，原有 `camera` / `preview` / `depth_preview` 和 `frame` 仍对应 `wrist_rgb`。
`SharedCamera(..., camera_id="exterior_rgb")` 可读取另一台设备的原始 RGB。
原始 RGB 通过已有 PyZMQ 的本地 IPC multipart 传输（JSON 元数据 + BGR 像素），不经过网页缩略图或 Base64；控制和监视信息继续使用原有 JSON 接口。录像复用 FFmpeg/libx264。
网页 `POST /api/camera` 接收 `camera_id` 与布尔值 `enabled`。

关闭相机会停止 RealSense 管线、释放设备，保留 IPC 服务，以便重新开启。
刷新网页、退出或重新启动网页不会改变已经运行的相机服务开关状态。
录制期间禁止关闭；启动录制与关闭相机通过同一个跨进程锁互斥。
旧版遥操不支持重连和录制锁，在旧会话退出前会拒绝关闭相机。
更新后启动的遥操能在手动关闭/开启后恢复相机读取。

这些开关不控制机械臂电机，也不改变 USB 头显追踪和广播设置。
`viewer_service.socket` / `port` / `camera` 可在本地配置中覆盖，默认为
`outputs/runtime/viewer.sock`、`18081` 和 `true`；camera 表示启动网页时确保相机服务存在，不强制重新开启已关闭的采集。

RGB 参数可在 `[camera_service.color]` 统一设置，单台覆盖使用 `[cameras.<名称>.color]`，示例见 `configs/local.example.toml`。卡片底部显示 SDK 回读的白平衡、曝光和增益；悬停参数行或放大 RGB 画面可查看亮度、对比度、饱和度、Gamma、锐度等。自动模式只显示“自动”，不把静态设置值当成逐帧测量值。配置变化需重启相机服务；录制期间不能重启。

## 双相机录制和质量结果

双路各自写入 `wrist_rgb.mp4` / `exterior_rgb.mp4` 与 MCAP 帧索引，保留每台的原始时间戳、帧号、设备标识和 RGB 设置；不录深度。任一路缺失或过期都会阻止开始录制，录制中断流则保留已有文件并标记中断。主页面的 RGB 帧数按“腕部 / 外部”显示。

每条保存后在后台校验机器人状态、两路帧序列、实际频率、最大间隔、视频解码与主机时间偏差。`quality.json` 随原始数据保存并收入任务包；“上一条”显示检查中／通过／有问题，点击查看原因及分路统计。保存完整、数据质量通过、人工确认任务成功是不同状态。检查不会占用控制线程，下一条可以继续录制；任务打包会等待已有质量检查结束。

网页回放按同一播放时刻读取两路各自最近的此前帧，未到第一帧或超过录制的间隔阈值时显示缺帧，不把实时视频混入回放。旧数据仍只显示腕部。图像与机械臂按主机接收／采样时钟对齐，不宣称硬件曝光同步。

相机权限需一次性安装：`bash scripts/setup/fix-camera-permissions.sh`。规则只匹配 D435/D435i，让已有 plugdev 组用户在重启后仍能访问设备；安装时请求 sudo，不启动机械臂。

## 腕部 IMU

相机角色按序列号配置：本机 D435i 作为腕部，D435 作为外部。更换腕部相机后需要针对新安装重新做手眼标定，`hand_eye_calibrated` 保持 false。

底部 IMU 卡片展示 SDK 相机局部坐标系中的加速度（m/s²，含重力）和角速度（rad/s），不把它们当成姿态角。分别以 200 Hz 读取，网页展示最新值；离线或过期显示空值。录制时每张 RGB 帧携带最新 IMU 快照及各自原始时间戳，当前不保存完整高频 IMU 流。

若 RGB 在线但 IMU 报 Permission denied，重新运行 `bash scripts/setup/fix-camera-permissions.sh`。新增规则仅为 D435i 的 IIO 节点和 sysfs 属性授予 plugdev 权限；脚本需要 sudo，重开相机服务，录制时拒绝重启，不启动机械臂。
