# 独立机械臂服务与三维监看

机械臂通信、相机采集、控制输入和三维监看分别由独立进程负责。`arm-service` 持有设备，持续采样和发布状态；Quest、终端和手眼标定通过本机接口申请控制权；`view-arm` 只订阅状态，不打开 CAN、Quest 或相机。

```text
Quest / 终端 / 手眼标定 → 本机控制接口 → arm-service ↔ X5 / 虚拟后端
                                           ↓
                                        状态流
                                           ↓
                                  view-arm → 浏览器
```

## 真机使用

在各自的终端中启动，服务可一直保留：

```bash
# 终端 1：连接真机，持续反馈，初始为阻尼待机。
./启动机械臂服务.sh
# 等价：./run.sh arm-service

# 终端 2：三维监看；打开输出的网址。
./scripts/viewer/启动仿真.sh
# 等价：./run.sh view-arm

# 终端 3：自动唤醒 Quest 并启动遥操。
./启动遥操.sh
# 遥操入口默认开启相机/采集会话；录制仍需 ./run.sh record start --task "任务描述"

# 其他终端：只读取服务反馈，不申请控制权，不改变当前控制模式。
./run.sh check-arm
```

**启动真机服务是主动通信。** 当前 SDK 的初始化和 `recv_once()` 包含使能/阻尼操作，不是被动 CAN 监听；服务启动不会自动回零或设定预设姿态。阻尼不等于位置保持，启动和退出时应支撑机械臂。只启动监看不会启动 SDK 或使能电机。

没有控制程序时，服务仍提供反馈，页面显示“真机反馈 · 待机 · 阻尼待机”。正常退出控制端会释放控制权并请求阻尼，服务和监看继续运行。控制进程崩溃或超过 0.5 秒未续约时，服务清除待执行目标、撤销控制权并请求阻尼。旧客户端不会自动恢复控制，需重新启动控制程序。

关闭监看不影响服务或控制；停止服务后监看保留最后姿态，超过 1 秒标记过期。重新启动服务后页面恢复，旧控制客户端必须重新连接；不重放旧指令。服务进程本身被 SIGKILL、设备断电或 CAN 故障时，软件不能保证电机成功进入阻尼。

## 虚拟机械臂

服务选择虚拟后端，监看命令完全相同。以下三个命令分别在三个终端运行：

```bash
./run.sh arm-service --backend simulated
./scripts/viewer/启动仿真.sh
./run.sh control-arm
```

第三个终端也可选择 `./run.sh control-arm --input quest`、`--input idle`，或 `--replay outputs/calibration/plan.json`。只选择一个控制方式；第二个控制端无法抢占已有控制权。`control-arm` 要求服务是虚拟后端，连接真机服务会报错；真机入口也会拒绝连接虚拟服务。没有启动服务时，控制端报告服务缺失，不自动创建另一台虚拟机械臂。

`control-arm` 的终端命令为 `q J1 ... J6`、`ik x y z rx ry rz`、`fk`、`exit`。单位为 rad/m，IK 旋转用旋转向量。初始姿态由服务 `--q` 设置，默认 `[0, 1.5, 1.45, -1.52, 0, 0]`；更换控制端不会重置姿态。`control-arm --headless` 仅离线校验，配合 `--replay` 检查计划，无需服务。

## 配置与接口

`configs/project.toml` 的 `[arm_service]` 集中定义后端、控制接口、SDK preview、采样率、速度/软限位和夹爪参数；`configs/local.toml` 可覆盖。真机 CAN 和模型仍由 `[robot]` 指定。硬件参数不再分散到 presets / collection profile；这些 profile 只定义输入、控制速度请求和采集选项。控制端显式传入的速度覆盖服务默认速度，未传时才使用服务配置中的默认值。每次申请控制权都会重新选择速度，不继承上一个控制者的覆盖值。

当前 presets / collection 的位移比例为 `1.0`，请求速度和服务默认速度均为 `2.0 rad/s`。日常可直接修改 `启动遥操.sh` 顶部参数并重启遥操；修改服务默认配置时需要重启服务。速度是上限，实际运动仍受指令超前限制和 SDK 控制响应影响。

控制接口默认 `outputs/runtime/arm.sock`，为权限 0600 的 Unix `SOCK_SEQPACKET` socket。服务独占设备锁、控制接口和状态发布地址后才初始化硬件。单个服务只允许一个控制者，其他客户端可以读取反馈。客户端 `--service-socket` 与服务 `--socket` 可指定其他本机通道；标定读取配置中的地址。

协议包含实例 ID、模型/坐标系、控制 token、递增命令序号和本机单调时间戳。过期请求、重复序号、非法数值、错误模型或真机/虚拟类型均拒绝。RPC 连接等待不会阻塞设备循环；每周期最多应用一个最新目标，仍保留原有 SDK 指令限速、0.05 rad 超前限制和夹爪保持。状态采样与指令提交均在服务线程进行；读取请求会额外采样 SDK 缓存，便于标定在相机读取前后取得机械臂快照。

`[telemetry].endpoint` 默认 `tcp://127.0.0.1:5567`。服务通过 ZeroMQ PUB 以 20 Hz 发布，监看使用 SUB；仅保留最新状态，丢帧或没有订阅者不阻塞控制。监看支持 `--endpoint`、`--port`、`--urdf`、`--eef`、`--viewer`；底层 HTTP 默认随机端口；日常 `scripts/viewer/启动仿真.sh` 固定为 `http://127.0.0.1:8081/`，重启后刷新原页面即可，可用 `--port` 覆盖。

状态快照含 `schema=1`、服务实例对应的 `stream_id`、模型哈希/关节名/单位、`source`（真机/虚拟、输入、阻尼/控制）、六轴反馈与目标、采样和发送时间、路径。服务内更换控制者保留实例 ID 与机械臂当前姿态；服务重启会清空旧轨迹。非法或过期数据不被当作实时反馈。

## 采集与扩展边界

原始 episode 仍由控制进程中的 `TeleopSession` 录制，D435i 由独立共享服务持有，录制读取原始 BGR 帧并保留设备时间戳和主机接收时间。服务反馈的采样时间保留为 `host_monotonic_ns`，接收时间另外记录为 `host_received_monotonic_ns`；`service_command` 记录该反馈时刻前最近应用的输入请求，`submission` 是最近实际提交给 SDK 的安全航点。二者和 SDK 插值输出分别保留。RPC 返回最近一次采样，不能假设它已包含刚发出的指令结果。

SDK 时间戳只说明其控制循环推进，不能证明逐电机 CAN 帧的新鲜度。三维状态流可能丢帧，不能作为训练录制通道。π0.5 尚未接入；后续策略可直接使用 `robot_control.client.ArmClient` 提交目标，监看无需增加控制模式。

`check-arm` 已改成只读服务客户端。历史 `teleop` / `teleop-dry-run`、官方 ARX 实验入口和 `test-joint` 仍是独立诊断路径，使用设备锁，运行它们前需停止机械臂服务。它们不用于日常采集。数据集离线回放仍可自行发布状态，默认通道已有服务时会拒绝第二个发布者。

本次验证仅使用虚拟后端和 SDK mock，未启动真机服务或执行真机动作。测试日志见 `outputs/logs/arm-service-tests.log`、`arm-service-browser-tests.log`。

`./启动遥操.sh` 默认传入 `--enable-session`，采集会话读取共享相机服务，不会自动开始录制。可用 `--no-enable-session` 关闭会话，此时网页保留机械臂状态，手柄显示未连接，相机仍独立显示。直接调用底层遥操命令时需显式加 `--enable-session`。相机异常不会中止遥操，但会阻止采集。

网页通过只读 `/api/sensors` 获取本机相机服务及遥操会话数据，不初始化相机或 Quest SDK，不发送录制或机械臂命令。RGB 预览为 320×240、约 5 Hz，采集原始分辨率不变；同时显示原生深度伪彩色预览，不显示 IMU。手柄显示数据采样约 10 Hz，页面约 5 Hz 查询；“样本年龄”表示服务端查询时距离该监看快照采样经过的时间，不是手柄到机械臂的动作延迟。100 ms 的采样门槛由约 20 ms 的控制循环检查，因此快照间隔可能为 100–120 ms，年龄在这个范围内循环变化属预期。SDK 时间戳保护检查整体帧进展，不能证明每个手柄的追踪状态，也不推测电池电量。超过 0.5 秒的预览/手柄数据会被清掉并提示过期。停止遥操会关闭其采集会话；机械臂监看仍独立运行。


日常遥操脚本在交互终端提供命令（回车确认）：`w` / `1` 模拟佩戴并启动遥操，`s` / `2` 停止遥操后请求头显休眠，`p` 查看子进程状态及日志路径，`q` / Ctrl+C 停止遥操并退出终端。退出本身不改变头显电源，需要节电时先输入 `s`。从强制休眠后的停止状态唤醒会建立新进程；从取消模拟佩戴状态恢复则复用原进程。机械臂服务持续运行。

终端将启动信息和异常保存到 `outputs/logs/teleop-console-*.log`；若遥操启动失败，输入 `p` 查看退出码，再检查该日志。状态仅报告进程存活，不保证 Quest 追踪正常。`--help` 不唤醒设备，非交互调用继续以前台进程方式运行。

原 `OFFICIAL BASELINE` 连续输出已取消，网页“控制误差”显示 IK 步长峰值、IK 积压和命令跟踪误差（rad）；悬停关节快照可看 `q_actual/q_des/q_safe`。这些是最近一次 0.2 秒诊断采样，不是实时逐关节安全告警；过期后不显示旧值。此改动涉及机械臂服务内的硬件适配器，需要在停止控制后重启服务才能移除旧进程的打印。


`u` / `3`：取消模拟佩戴，不发送强制休眠按键，不退出遥操进程。程序先暂停输入、取消预设并释放机械臂控制权，再发送 `prox_far`，由 Quest 根据实际佩戴和息屏策略关闭屏幕。相机和会话保留，但暂停期间没有新遥操采样，不应跨暂停录制一段连续动作。

再次输入 `w` / `1` 会唤醒头显、恢复模拟佩戴并启动 Quest 客户端；同一遥操进程自动等待新的连续时间戳，从当前机械臂反馈重建参考。Grip/A/B/右摇杆按键必须先松开，随后正常按 Grip 操作，无需重新配置。恢复期间尚无数据时保持暂停；意外断流仍沿用停止控制的保护。若会话不可用（例如禁用了 `--enable-session`），终端不会发送取消佩戴操作，会提示错误。

端口 8081 被占用时启动失败，不会偷偷换地址；可以修改 `scripts/viewer/启动仿真.sh` 中的 `WEB_PORT` 或传入 `--port 8082`。


`./scripts/viewer/启动仿真.sh` 默认确保独立 `camera-service` 正在运行；服务以 `[camera_service].socket` 提供只读图像与预览，多个页面及录制共用一路 D435i。关闭网页、退出监看或遥操都不关闭共享相机。相机服务日志在 `outputs/logs/camera-service.log`；也可用 `./run.sh camera-service` 在单独终端前台运行，用 Ctrl+C 停止。每台配置相机只能有一个服务实例。设备断开后服务每 2 秒尝试重新打开；录制检测到断帧仍会报错，不静默拼接数据。

只看模型或没有相机时可用 `./scripts/viewer/启动仿真.sh --no-camera`，它不会自动启动相机服务（已运行的服务仍可读取）。页面首先显示明确标注的参考模型姿态，反馈栏留空；收到机械臂服务状态后自动显示真实/虚拟反馈。监看不会自行启动或使能真机，真实关节数据仍需要机械臂服务。相机初始化和曝光稳定需要短暂时间，不依赖 Quest 或遥操启动。


D435i 相机服务同时开启 640×480（默认）、30 Hz 的 BGR8 和 Z16 流。网页 RGB/深度预览约 5 Hz，深度颜色固定映射 0.2–2 m，范围外饱和显示、无效零深度为黑色。深度使用设备的米制比例，不逐帧自动拉伸颜色；它是原生深度视角，未对齐 RGB，不能直接对照两个画面的像素。手眼外参仍未标定。深度目前用于监看，episode 仍保存原有 RGB，不额外写入原始深度。升级后需重启旧相机服务以开启深度流。

侧栏各模块在桌面、较矮窗口和窄屏档位使用固定网格尺寸；状态文字、画面断流不会改变模块大小。窗口跨越尺寸档位时重新排版，保持一页无滚动条。

正常遥操的 IK 输出超出关节范围时，在发送前截断到对应关节上下限；控制连接和 Grip 状态保持，反向移动手柄即可离开边界。网页显示“限位 J…”，超过 0.5 秒的提示会清除。底层速度、软限位和指令超前保护仍保留；预设/外部接口参数仍需合法，NaN、无穷大或通信故障不会当作正常限位继续执行。后台控制线程异常会传到主进程，终端主动报告子进程退出和错误摘要；相机继续运行时网页也会明确显示遥操会话未连接。


页面底部显示独立的实测耗时（ms），并标注“端到端未测”：
- 指令确认：本机控制客户端开始构造发送请求，到机械臂服务返回成功接收应答的耗时；包含本机 IPC，不包含后续设备执行、电机动作或到位时间。
- 手柄处理：通过输入新鲜度检查后，从读取机械臂状态、更新手柄/夹爪和预设逻辑，到完成 IK 的本机耗时；不含 Quest 追踪、USB/Wi-Fi 网络传输和控制线程排队时间。

两者使用同一主机单调时钟计时，不拿 Quest 时钟直接相减。超过 0.5 秒未更新或会话断开显示“—”；读取状态不会刷新指令确认指标。手柄区域的“样本年龄”继续独立显示。这些耗时不能相加作为“手柄动作到机械臂响应”的端到端延迟。


连接指标以本段为准：网页已移除“样本年龄”、相机年龄和手柄处理耗时的数值展示，采样时间仅在内部用于过期判断。底部每秒更新：
- 机械臂服务 RTT：监看进程向本机 arm-service 发出只读 describe 查询至收到应答的往返时间。不申请控制权，不初始化 SDK；不是 CAN 总线或电机响应延迟。
- Quest USB RTT：通过已授权 USB 设备的持续 ADB shell 回显通道测量请求/应答，排除通道启动时间。包含 USB、ADB 和头显端调度，不代表 XR 协议的端到端处理时延，也不证明当前 XR 流一定走 USB。只有唯一已授权 USB 设备时才测量，不执行唤醒/休眠或重连命令。

无测量结果或超时显示“未测”，超过 3 秒的测量结果也会丢弃。探测在后台独立线程执行，默认每秒一次，不阻塞机械臂渲染或遥操控制。监看退出时关闭回显进程；可用 `--no-connections` 禁用探测。
