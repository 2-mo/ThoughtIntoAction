## 双臂遥操

| 控制 | 左手柄 → `192.168.1.19` | 右手柄 → `192.168.1.18` |
| --- | --- | --- |
| 机械臂跟随 | 按住左 Grip | 按住右 Grip |
| 停止对应机械臂 | 松开左 Grip | 松开右 Grip |
| 张开夹爪 | 松开左 Grip，按住 X | 松开右 Grip，按住 A |
| 闭合夹爪 | 松开左 Grip，按住左 Trigger | 松开右 Grip，按住右 Trigger |
| 结束整个会话 | Y | B |

启动先松开两个Grip。重新握持从对应机械臂的实测位置接续，不扩大以启动位置为中心的会话范围。两侧可分别跟随；夹爪只要求对应手柄松开Grip。夹爪松键停止安排下一段，已接受的一段可能继续，B/Y退出也不保证中止该段。

先运行只读预览，分别移动两侧手柄，核对日志的 `hand`、`host`、`xr_fresh` 和目标方向：

```bash
./run.sh realman quest-dual --position-only --duration 30
```

确认两台安装坐标、工具负载及各自运动空间后，现场执行：

```bash
./run.sh realman quest-dual --position-only --execute --gripper --duration 30
```

`--position-only` 保持每次握持时的末端姿态。省略此参数则同时映射手腕旋转。默认平移速度上限仍为0.06m/s，缩放0.6；本次接入不提高速度。夹爪默认50/1000单位分段，可用 `--gripper-step 100` 增大，松键后的剩余行程也相应增大。

`--config` 指定右臂配置，`--left-config` 指定左臂配置；默认分别为 `rm65-18.json` 和 `rm65-19.json`。拒绝两个配置使用同一主机或不同控制频率。两台均通过身份和初始状态检查后才进入控制，任一侧机械臂错误、输入无效或通信异常都会退出，并逐台尝试停机；即使一台停止指令失败，也会尝试停止另一台。夹爪有效反馈报告离线时仅暂停该侧夹爪，待对应Grip、张开键和Trigger都松开后按既有规则只读恢复，恢复后需要重新按键。

`.18` 夹爪是否在线仍需现场确认，可先运行上面的 `gripper-status --config ...18.json`。`--gripper-initialize-open` 是显式启动全开动作，**双臂时会依次完全打开两只夹爪**，不应作为普通重连参数；该动作和双臂运动本次均未执行。

两台保留各自的超时、速度、反馈领先量、关节步长及工作范围保护。这里没有双臂碰撞检测或同步轨迹规划，单臂范围并不能保证两臂互不接触。SDK当前只提供全局XR时间戳，没有每只手柄独立的新鲜度/连接标志；`xr_fresh=true` 表示共享流更新，不能单独证明两只手柄都在追踪。首次现场验证应分别检查两只手柄与两台的方向，然后再同时操作。
