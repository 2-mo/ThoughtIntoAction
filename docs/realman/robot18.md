## 双臂遥操

| 控制 | 左手柄 → `192.168.1.19` | 右手柄 → `192.168.1.18` |
| --- | --- | --- |
| 机械臂跟随 | 按住左 Grip | 按住右 Grip |
| 停止对应机械臂 | 松开左 Grip | 松开右 Grip |
| 张开夹爪 | 按住 X，可同时握左 Grip | 按住 A，可同时握右 Grip |
| 闭合夹爪 | 按住左 Trigger，可同时握左 Grip | 按住右 Trigger，可同时握右 Grip |
| 结束整个会话 | Y | B |

启动先松开两个Grip，并松开X/A与Trigger解锁。重新握持从对应机械臂的实测位置接续，不扩大以启动位置为中心的会话范围。两侧可分别跟随，移动和夹爪可同时操作；握持或松开Grip不会清掉夹爪请求。夹爪松键停止安排下一段，已接受的一段可能继续，B/Y退出也不保证中止该段。

先运行只读预览，分别移动两侧手柄，核对日志的 `hand`、`host`、`xr_fresh` 和目标方向：

```bash
./run.sh realman quest-dual --position-only --duration 30
```

确认两台安装坐标、工具负载及各自运动空间后，现场执行：

```bash
./run.sh realman quest-dual --position-only --execute --gripper --duration 30
```

`--position-only` 保持每次握持时的末端姿态。省略此参数则同时映射手腕旋转。按用户的加速要求，默认平移速度上限由0.06调为0.10m/s、缩放由0.6调为1.0、角速度上限由0.2调为0.35rad/s。夹爪默认分段由50增至100/1000单位，查询间隔由0.15缩短为0.08秒；可用 `--gripper-step 50` 选择更细分段。仍等待每段到位，不能保证瞬时松键停止或实际速度达到上限。

`--config` 指定右臂配置，`--left-config` 指定左臂配置；默认分别为 `rm65-18.json` 和 `rm65-19.json`。拒绝两个配置使用同一主机或不同控制频率。两台均通过身份和初始状态检查后才进入控制，任一侧机械臂错误、输入无效或通信异常都会退出，并逐台尝试停机；即使一台停止指令失败，也会尝试停止另一台。夹爪有效反馈报告离线时仅暂停该侧夹爪，对应张开键和Trigger松开后按既有规则只读恢复，可以保持机械臂跟随，恢复后需要重新按夹爪键。

两台夹爪现已只读确认在线。普通位置分段沿用控制器先前的速度与力，协议没有单独的速度字段；加大分段和缩短查询间隔减少调度等待，不代表物理速度必然提升同样倍数。需要显式设置速度时，可在空载并留有完全张开空间的条件下运行下面的命令，**启动时会依次完全打开两只夹爪**，再以控制器速度300/1000执行位置分段；不是只修改参数或普通重连：

```bash
./run.sh realman quest-dual --position-only --execute --gripper --gripper-initialize-open --gripper-speed 300 --duration 30
```

`--gripper-speed` 范围1..1000，只用于显式启动张开或独立 `gripper-open/close --execute`，默认100；单独与普通分段会话一起传入会报参数错误，避免误以为位置命令已经设置速度。本次未发送新的整程开合或双臂运动。

两台保留各自的超时、速度、反馈领先量、关节步长及工作范围保护。这里没有双臂碰撞检测或同步轨迹规划，单臂范围并不能保证两臂互不接触。SDK当前只提供全局XR时间戳，没有每只手柄独立的新鲜度/连接标志；`xr_fresh=true` 表示共享流更新，不能单独证明两只手柄都在追踪。首次现场验证应分别检查两只手柄与两台的方向，然后再同时操作。
