## 双臂遥操

| 控制 | 左手柄 → `192.168.1.19` | 右手柄 → `192.168.1.18` |
| --- | --- | --- |
| 机械臂跟随 | 按住左 Grip | 按住右 Grip |
| 停止对应机械臂 | 松开左 Grip | 松开右 Grip |
| 张开夹爪 | 按住 X，可同时握左 Grip | 按住 A，可同时握右 Grip |
| 闭合夹爪 | 按住左 Trigger，可同时握左 Grip | 按住右 Trigger，可同时握右 Grip |
| 结束整个会话 | Y | B |

启动先松开两个Grip，并松开X/A与Trigger解锁。重新握持从对应机械臂的实测位置接续，丢弃此前未完成的手柄目标。两侧可分别跟随，移动和夹爪可同时操作；握持或松开Grip不会清掉夹爪请求。夹爪松键停止安排下一段，已接受的一段可能继续，B/Y退出也不保证中止该段。

先运行只读预览，分别移动两侧手柄，核对日志的 `hand`、`host`、`xr_fresh` 和目标方向：

```bash
./run.sh realman quest-dual --duration 30
```

确认两台安装坐标、工具负载及各自运动空间后，现场执行：

```bash
./run.sh realman quest-dual --execute --gripper --duration 30
```

平台默认完整六自由度：三个平移轴与三个旋转轴均跟随手柄，平移和旋转增量缩放均为1.0，六个关节通过逆运动学共同参与，没有锁定某个关节。`--position-only` 是可选的仅平移模式，保持握持时的末端朝向。 真机按相邻有效手柄位姿的增量跟随，以最后实际提交的限速目标为基准，不累计未发送的位移。超过当前周期速度预算的手柄位移会被丢弃，因此高速挥动不保证最终位置仍是绝对1:1。平移变化小于0.3mm、旋转变化小于0.002rad时暂不更新目标；小变化会累积到超过门槛再响应。手柄约80ms未发生有效运动，发送机械臂停止并清除未跟上的目标；期间仅短暂重复最后已提交目标，不推进旧目标。再次移动从实测位置接续；松开Grip仍立即请求停止。阈值与检测时间是软件规则，不是实测物理停止时间保证，静止时仍可操作夹爪。

2026-11-03两台只读查询得到控制器最大线速度0.25m/s、最大角速度0.60rad/s；当前使用平移0.25m/s、旋转0.30rad/s。关节上限实读为180、180、225、225、225、225°/s，平台取50%，即90、90、112.5、112.5、112.5、112.5°/s；按每周期实际间隔计算候选关节步长，替代原固定1°检查。反馈领先范围按有效速度乘0.3秒超时预算计算，为0.075m、0.09rad，替代原固定1cm门槛。只读取控制器参数，不写入控制器持久速度或关节限位。以上是软件指令上限，不保证实机达到该速度。

夹爪默认分段100/1000原始单位，查询间隔0.08秒；可用 `--gripper-step 50` 选择更细分段。仍等待每段到位，不能保证瞬时松键停止。

`--config` 指定右臂配置，`--left-config` 指定左臂配置；默认分别为 `rm65-18.json` 和 `rm65-19.json`。拒绝两个配置使用同一主机或不同控制频率。两台均通过身份和初始状态检查后才进入控制，任一侧机械臂错误、输入无效或通信异常都会退出，并逐台尝试停机；即使一台停止指令失败，也会尝试停止另一台。夹爪有效反馈报告离线时仅暂停该侧夹爪，对应张开键和Trigger松开后按既有规则只读恢复，可以保持机械臂跟随，恢复后需要重新按夹爪键。

两台夹爪现已只读确认在线。普通位置分段沿用控制器先前的速度与力，协议没有单独的速度字段；加大分段和缩短查询间隔减少调度等待，不代表物理速度必然提升同样倍数。需要显式设置速度时，可在空载并留有完全张开空间的条件下运行下面的命令，**启动时会依次完全打开两只夹爪**，再以控制器速度500/1000执行位置分段；不是只修改参数或普通重连：

```bash
./run.sh realman quest-dual --execute --gripper --gripper-initialize-open --gripper-speed 500 --duration 30
```

`--gripper-speed` 范围1..1000，只用于显式启动张开或独立 `gripper-open/close --execute`，默认500（50%）；单独与普通分段会话一起传入会报参数错误，避免误以为位置命令已经设置速度。启动日志同时记录百分比、控制器原始最大速度及有效软件速度；速度查询缺失或无效时拒绝启动，不猜测额定速度。

两台保留各自的超时、速度、反馈领先量、关节步长、控制器关节限位和奇异区检查。这里没有双臂碰撞检测或同步轨迹规划，取消软件会话半径后尤其不能据此判断桌面或双臂碰撞空间。SDK当前只提供全局XR时间戳，没有每只手柄独立的新鲜度/连接标志；`xr_fresh=true` 表示共享流更新，不能单独证明两只手柄都在追踪。首次现场验证应分别检查两只手柄与两台的方向，然后再同时操作。

## 从平台进入，只用手柄操作

本机 `configs/local.toml` 已设置 `[workbench] robot_start = "realman-dual"`。在项目根目录执行 `./run.sh`，交互打开工作台时启动 `./run.sh robot-pair`。后台 `bench start --detach` 不启动机器人；总控 `6` 为 RealMan，`4/5` 为 ARX 仿真。已有会话复用，不重复连接设备。Toolkit、USB传输、相机与网页仍独立运行。

平台新入口复用 main 的控制架构：一个原生 Quest SDK 进程发布双手输入；左右各一个标准 workbench、控制内核、原生 router/coordinator 和命令网关。每侧驱动用控制器实读 DH 与厂商离线算法求解，通过 `movej_canfd` 下发全部六个关节，不再让控制器做一次笛卡尔逆解。相对映射、控制权、规划、采集与策略接口继续使用平台实现。

RealMan与ARX通过同一插件注册表选择，切换使用已有配置入口，不在控制内核中判断机械臂型号：

| 层 | ARX | RealMan |
| --- | --- | --- |
| 真机驱动 | `arx.real` | `realman.real` |
| 设备配置 | `arx5` | `realman.hardware` |
| 规划运动学 | `arx5` | `realman.hardware`（名义RM65模型） |
| 手动工作台 | `real-manual` | `realman-manual`（默认左臂，可在配置中选右臂） |

停止当前机器人会话后，可用 `./run.sh kernel profiles start --profile real-manual --headless` 切回ARX，或 `--profile realman-manual --headless` 单独启动RM65标准内核供命令 / 策略使用。日常双臂手柄使用 `./run.sh robot-pair`；`realman-left/right` 是它生成部署时使用的共享输入模板，不能脱离输入所有者独立当作Quest入口。

启动只连接和读取，不自动使能、清错、回位或开爪。连接、工具或机械臂控制器故障不满足要求时明确失败；修复后重新运行，不自动恢复运动。完整夹爪反馈报告离线、未使能或故障时只暂停该侧夹爪，不阻止机械臂内核启动；未知宽度记为 `null`，不伪装成零开口。4099 是不可达 / 奇异点错误，不能靠取消平台范围或更换 SDK 绕过。

| --- | --- |
| 左 X / 右 A 按住150ms后松开 | 切换对应侧模式；与 main 原生 Quest 一致 |

B/Y 不使用旧独立双臂会话的开始 / 暂停语义，现作为上述显式初始化手势。P/H/D 属于 ARX 操作面板，双臂面板不发送这些动作；关闭双臂进程请求两侧停止。启动和停止不调用 ARX 回零或阻尼流程。
