## 三相机接入

沿用共享 RealSense 服务、网页独立卡片和 `collect run --cameras`，不在机械臂内核中打开相机。每个序列号仅由共享服务持有；本机序列号保存在不提交的 `configs/local.toml`，可提交示例见 `configs/local.example.toml`。

| 相机 ID | 安装位置 | mount / robot_side |
| --- | --- | --- |
| `wrist_rgb` | 左臂 `.19` 腕部 | `wrist` / `left` |
| `right_wrist_rgb` | 右臂 `.18` 腕部 | `wrist` / `right` |
| `exterior_rgb` | 侧面固定机位 | `fixed` |

三台均为 D435，RGB 为640×480、30 FPS，原生深度预览同档位；录制保存RGB，不录深度。`[recording].camera_ids` 列出以上三路，工作台 **C** 按这个列表生成采集命令，不再写死两路。网页每台可独立开关、放大及显示深度；回放补齐右臂画面。名称、安装类型和所属机械臂随相机元数据保存。**一条采集仍记录所选 RUN 的机械臂状态加三路图像，不是双臂状态联合录制。**

工作台用 **[ / ]** 选择机械臂后，**H** 按本侧 `robot_side` 选择腕部标定相机；没有唯一对应项时不提供该标定动作，避免把左相机标到右臂。**J** 仍选侧面相机。三台均未完成手眼／固定外参标定，不复用旧ARX安装的外参。

在仓库根目录加载新配置（仅重启共享相机服务，不重启机械臂；已有录制时拒绝重启）：

```bash
cd /home/guest/下载/ThoughtIntoAction-local
./run.sh bench restart --target camera
./run.sh bench restart --target interfaces
```

随后刷新监看网页，预期显示左臂、右臂、侧面三张卡片及各自RGB／深度状态。左臂与侧面枚举为USB 2.1、右臂为USB 3.2；SDK能解析三台的配置，但本次未启动视频管线，三路并发帧率、丢帧及USB带宽仍需现场核对。

当前机器缺少 `ffmpeg`，默认MP4录制尚不可用。可先使用既有PNG方式（将 `<RUN>` 替换为所选臂实际运行目录）：

```bash

  --cameras wrist_rgb,right_wrist_rgb,exterior_rgb --rgb png --duration 20
```

预期输出 `outputs/datasets/runtime/episode_*/`，包含三路独立PNG目录与MCAP帧索引；PNG占用更多磁盘。要使用默认MP4，先按系统包管理方式安装 `ffmpeg`。本次14项针对性测试通过：三路IPC身份、采集参数、元数据、独立开关／故障、标定选择和PNG录制／导出；MP4测试因缺少ffmpeg跳过。前端模块语法检查通过；Playwright依赖缺失，未执行浏览器视觉验收或真实相机出帧验收。

## 2026-11-05：现有真机路径的速度与夹爪调整

继续使用 `codex/realman-following-fix`、现有 Quest 输入、目标控制器和 JSON 协议。

- 两台连接配置的 `speed_percent` 从50改为100，硬件 profile 同步取消90／112.5°/s关节上限。实际关节预算取控制器读回、profile及CANFD协议180°/s上限的最小值；默认25 Hz对应最多7.2°/周期。实时位姿／关节流取消额外0.25 m/s平移及0.30 rad/s旋转的笛卡尔截断，包括无新包时继续处理缓存目标的周期。规划曲线仍检查其笛卡尔预算（读回值与profile 0.25 m/s、0.30 rad/s的较小值），不会静默压缩规划轨迹。运行参数 `streaming_cartesian_speed_limits=null` 明确区分实时跟随与规划限速。不是完全无关节约束，也不是实测速度承诺；没有写入控制器持久参数。
- 标准平台夹爪沿用 `max_width * (1 - trigger)` 的线性开口映射，直接发送该目标的 `set_gripper_position`，取消每100原始单位（名义7 mm）拆段。因此一次全闭合或张开目标只需一次位置命令，不再每7 mm刹停并等待反馈。范围仍为1～1000，保留接触、到位／过冲判定、5秒超时、离线恢复和松键解锁。
- 当前旧版协议没有保证运动中覆盖目标的语义，也没有已适配的独立夹爪停止命令，仍等待当前动作完成／接触后采用当时最新目标。**中途反向不会立即生效；撤下输入后已接受动作可能继续到目标，剩余行程不再限于7 mm。** 本修改不承诺严格匀速或实时连续伺服；夹爪沿用设备已有速度／力设置。
- 两个连接配置也用于独立 `realman quest/quest-dual` 诊断入口，因此其关节／旋转百分比同步为100，但独立诊断仍保留自身笛卡尔限速；其按钮式 `Jog` 仍保留原分段方式。本节覆盖下文历史记录中的50%及标准平台100单位拆段说明。

协议依据：已缓存的[官方夹爪适配文档](https://github.com/RealManRobot/Dev_Center/tree/main/RobotGen3/legacyversions/zh/json)（PDF blob `cf1910b79a039523d3a79da46cd663f3f063f52f`）允许一次到任意1～1000位置；[CANFD运动协议](https://develop.realman-robotics.com/robot/json/motionConfig/)要求帧间不超过10°、关节规划速度不超过180°/s。25 Hz继续使用低跟随；高跟随要求周期不超过10 ms，不能只翻转 `follow` 标志。

本轮验证：控制环境下27项真机驱动假设备测试通过；主环境下协议／配置测试与平台测试共65项通过（旧速度断言更新后单项复测通过）。覆盖实时跟随取消TCP截断、关节预算／较低读回上限、规划拒绝超限、夹爪整程单次发送、中间开口线性映射、忙时不排队、接触／停止／离线恢复；均不是现场真机运动验收。

代码修改不会热更新正在运行的内核。工作目录为仓库根目录，在现有工作台按 **S** 停止旧内核，再按 **6** 启动双臂真机，预期进入双侧待机，随后由操作者按原方式进入跟随。本轮不自动重启服务或发送真机动作；现场仍需核对速度、完整开合和中途反向延迟。

## 当前平台入口

工作目录为仓库根目录。沿用现有入口，不需要改用独立 RealMan 演示程序：

```bash
./run.sh                           # 原工作台，默认 RealMan 双臂真机待机
./run.sh sim start                 # 同一工作台，RealMan 双臂 Quest 仿真
./run.sh kernel profiles start --profile sim-manual --headless
./run.sh examples sim_control      # 默认 RM65，普通 Robot API 不变
```

已有运行不会因改配置自动重启。先在原工作台停止旧 robot，再按 4 / 5 选择有／无 Quest 的 RealMan 仿真；重新运行 `./run.sh` 更新界面。控制台网页源码的模型已切换到仓库 RM65 URDF／网格，需使用原有网页构建入口更新静态产物。

双臂总控显示当前操作侧，默认左侧；真机对应左 `.19`、右 `.18`。`[` 选左、`]` 选右，原 C/B/X/T/H/J 菜单自动填入该侧 RUN。手机和浏览器控制台在接管时使用同一选择，已取得控制权的会话不自动迁移。总控 `I` 释放／恢复当前侧 Quest 租约，沿用内核现有独占控制规则，不抢占别的输入。原按键 6 仍启动双臂真机手柄待机。

总控 `4` 和 `./run.sh sim start` 使用 `robot-pair --backend sim`：左右各一个 MuJoCo 内核，一个 Quest 进程发布双手输入，工作台网页同屏显示双臂。左 X / 右 A 按住至少 150 ms 后松开切换本侧模式，Grip 相对跟随，Trigger 控制本侧夹爪。总控 `5` 使用 `robot-pair --backend sim --source cli`，同样显示双臂，但不加载 Quest，控制权留给网页 / 动作 / 策略。两个仿真内核独立运行，网页底座为示意布局，不提供双臂之间的物理碰撞；单臂 `sim-manual`、`sim-quest` profile 仍可显式使用。

双臂 Quest 的左 Y／右 B 现用于对应侧回初始位：先松开 Grip、Trigger 与功能键，再单独按住 Y／B 至少 1 秒，继续按住直到到位，松开停止。目标读取本侧 `park_q`，当前仿真与真机配置均为 `[0°, 0°, 90°, 0°, 90°, 0°]`；回位使用既有受限关节目标，夹爪不动。Grip、Trigger、X/A 冲突或输入／控制权失效会取消，需全部松键再操作。B/Y不再触发夹爪初始化；该功能保留独立维护入口。6 项共享输入回归覆盖按住时长、松键、冲突、断流／控制权变化，以及 MuJoCo 实际回位和夹爪开口保持；未执行真机回位。

Quest 输入进程在启动时等待内核满足连续静止反馈条件，再申请控制权；不会因 `runtime.ready` 早于静止窗口而直接退出。已有控制权冲突、内核停止和运行中租约丢失仍报错，不自动抢占或恢复运动。USB/TCP 已连接后，头显仍须唤醒、客户端在前台并发送 Controller 数据；以 VR 面板左右手柄的跟踪状态为准。

同步读取真机反馈后，控制仲裁使用读取完成时的主机时间。不能用周期开始时间判断稍后收到的反馈，否则每帧都会被误判为来自未来，持续清空静止窗口。此修复保留原静止速度、持续时间和反馈超时阈值；使用假设备回归及现场日志离线回放验证，未自动重启或操作真机。

双臂网页按 20 ms 间隔读取反馈，短暂断流保留模型并灰显最后姿态，恢复后继续显示，不因丢帧重载整页。切换运行实例仍重新加载对应模型。Quest 原始手柄帧由输入插件在现有 observer 进程中只读订阅，经标准反馈流送到网页；不另开 SDK，也不从机械臂姿态推断手柄在线。左右手柄分别检查时效，输入过期后撤下按键与位姿数据。

双臂网页的简化夹指复用原夹爪显示组件，分别读取各侧实际／目标开口及该运行声明的最大开口（仿真40 mm，真机名义70 mm）；不把夹爪位置塞入12维机械臂关节向量。未知开口隐藏该侧活动夹指，避免画成虚假的闭合或张开。2026-11-04 用隔离 namespace 下的合成 Trigger，经现有原生协调器、路由、共享输入和 MuJoCo 后端验证了40 mm→接近0→40 mm；5项双臂显示测试及浏览器所用几何函数的0／半开／全开、未知反馈、旧Y轴夹爪回归通过。未执行浏览器视觉验收。同期真机两侧只读反馈仍为夹爪全零、未就绪，这与仿真原先缺少夹指显示是不同问题，不能用显示修复宣称真机夹爪已可用。

随后用户确认两侧空载及张开空间，授权各执行一次速度500/1000初始化张开。沿用 `realman gripper-open --execute --gripper-initialize-open --gripper-speed 500`，先 `.19` 后 `.18`，两次均接受；只读确认两侧 `enable=1,status=1,error=0,mode=1,actpos=1001`。记录：`outputs/diagnostics/realman-gripper-initialize-20261104-152954.json`。重启双臂真机工作台后，两侧 `gripper_ready=true`、名义开口70 mm，网页同样收到有效开口与夹指显示声明；没有新增控制流程或自动初始化逻辑。进入跟随后，先松开Trigger再按下才能解锁开合，Grip不必握住。

继续现场复测发现原生 float32 开口上界为 `0.07000000029802322 m`，严格大于配置 `0.07 m`，使真机报 `Invalid EG2 nominal width target` 并退出。最初只处理了上界编码误差；随后左侧闭合目标出现 `-1.108492577e-6 m` 的微小超调，再次导致双臂退出。根因是真机发送绕过了已有目标控制器的限幅结果。现改为发送该控制器处理后的开口，复用其有限数检查与 `[0, gripper_max_width]` 限幅；没有新夹爪输入时仍传 `None`，不重放缓存。底层发送仍严格检查范围，不扩大行程。5项相关回归通过，覆盖两个端点、非有限数拒绝、无输入不重放，以及失联恢复后松键解锁。

最初上界编码修复后的一次40秒现场只读采样，两侧各1002帧无错误；右Trigger覆盖0～1，右夹爪反馈从70 mm缩到27.16 mm并回到70 mm，控制权保持有效。左侧该轮Trigger始终为0，只验证就绪与70 mm反馈，不能计为左侧手柄开合验收。记录：`outputs/diagnostics/realman-trigger-follow-20261104-153732.json`。

复用控制器限幅后重新启动双臂真机，40秒只读采样无错误，两侧Quest输入就绪、夹爪反馈有效。该轮两侧Trigger均为0，左侧保持、右侧跟随，不能作为本次实际开合验收。记录：`outputs/diagnostics/realman-trigger-follow-20261104-155525.json`。

### 关节变化超限的步长缩减

固定笛卡尔速度在不同姿态下会对应不同的关节变化。离线逆解通过模型、关节范围、正逆解残差及奇异区检查，但相邻成功下发关节解变化超过该轴当前周期预算时，将本次相对上一条指令的平移和旋转步长一起减半，最多缩减4次（1/16）。每次都检查重新量化后的实际发送位姿；反馈超时、模型异常或五个候选均超限仍终止；平台待机模式下，单个候选无逆解或进入厂商奇异区只停止对应侧并清除旧目标，保持Grip不会自动重试；松开该侧Grip再握下，以实际反馈重新归零，另一侧与夹爪继续操作。当前姿态若确实处于奇异区，重新归零不能绕过厂商检查。不发送被拒绝的目标。这是离线指令步长约束，不是实际关节速度保证。

诊断 `joint_step_scale` 表示采用比例，`joint_step_rejections` 保存缩减前被拒绝的逐关节差值；例如0.5表示该周期减半。原笛卡尔速度、工作空间与反馈领先限制保留。新行为已通过假设备回归及当前姿态只读模型检查，真实跟随效果仍需现场短测。

上一版将未就绪状态锁定到会话结束，会让控制器随后恢复在线时按键仍无法操作。现按上文的中立按键与两次只读空闲反馈恢复。若全零反馈持续，不能仅凭它判定硬件断电，也不能绕过检查直接闭合。

空载、有完全张开空间时，可显式追加 `--gripper-initialize-open`。它在同一TCP连接启动时只发一次官方 `set_gripper_release`（默认速度500/1000，完全张开，非阻塞；可用 `--gripper-speed` 指定），然后使用正常状态检查与分段调度。仅对全零状态允许这一显式张开；非零故障、部分离线反馈仍拒绝，不清错、不使能、不修改电源或串口。该选项用于 `quest/quest-dual --execute --gripper` 或 `gripper-open --execute`，双臂时会依次张开两只，默认命令不自动执行整程开合。

```bash
# 工作目录：/home/guest/下载/ThoughtIntoAction-local
# 此命令启动时会完全张开夹爪，确保空载并留出空间：
./run.sh realman quest --position-only --execute --gripper --gripper-initialize-open --duration 30
```

2026-11-02 用户明确确认空载与空间后，实际发送一次速度100的张开命令并收到接受；同一连接观察到开口从-1逐步增大，随后新连接确认 `enable=1,status=1,error=0,mode=1,temperature=32,actpos=1000`。该次发送前状态已恢复在线，故不把它描述为全零状态初始化实机通过，也不能据此确定全零根因。记录：`outputs/realman/gripper-explicit-open-diagnostic-20261102.json`。本轮未执行真机闭合、分段运动或机械臂加速测试；假设备回归覆盖显式初始化、空闲恢复、不重放旧动作、按键互锁和6cm/s限速。
