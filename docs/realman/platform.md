# RealMan RM65-BI 平台接入与 Quest 遥操

本项目提供独立 RealMan JSON/TCP 后端，遵循平台 `RobotState`、`ControlCommand` 数据接口，并注册为 `arm:realman` 插件。使用 `./run.sh realman` 入口；不使用 ARX 的 CAN 初始化、使能、回零或固定 250 Hz 原生路由。运动预检查使用锁定版本的官方离线算法源码与原生库，不全局安装厂商 Python 包。

真机当前支持六轴 RM65 的状态查询、Quest 右手柄相对 TCP 位姿预览、显式开启的低速笛卡尔透传和下文的独立 EG2-4C2 夹爪控制。真机尚未接入通用工作台按钮、模型监看或录制流程，不支持关节目标和拖动示教。另有统一内核的 `realman.sim` 仿真插件，入口和模型边界见 [RM65 仿真](simulation.md)。换机械臂不能只改 IP：型号、协议、坐标系与末端配置均需重新核对。

## 配置与已确认状态

部署配置：`configs/robots/realman/rm65-19.json`。2026-11-02 对 `192.168.1.19:8080` 的实际只读查询结果：

- 型号 RM65-BI，控制/规划软件 V1.7.0，算法 1.5.2-0cabec5b。
- 系统错误列表 `[0]`。
- 工具 `Lq`，工具坐标 `[0,0,140000,0,0,0]`（Z=140 mm），配置负载 500（0.5 kg），质心配置为零；这不是实测负载或已验证的 TCP 标定。
- 工作坐标系 `Base`，位姿为零。

后端启动时核对型号、工具名/位姿及工作坐标系名/位姿，不写入配置、不清错误、不自动使能。Quest 会话每秒复查当前工具与工作坐标系，变化即退出。`RobotState` 的关节角为 rad，TCP 为 m + xyzw 四元数；未提供的速度和夹爪反馈为 NaN。`mode` 表示本软件控制状态，不代表电机实际上电状态。

`eno1` 需要能直达机械臂网段。当前附加地址 `192.168.1.100/24` 是临时地址，重启失效；没有该地址时，在本机执行 `sudo ip address add 192.168.1.100/24 dev eno1`，不要替换 DHCP 地址或默认路由。

## 只读操作

工作目录 `/home/guest/下载/ThoughtIntoAction-local`：

```bash
./run.sh realman status
./run.sh quest usb prepare --launch-client
./run.sh realman quest --duration 30
```

Quest 中打开 XRoboToolkit，选择头显与 Controller 数据，IP 填 `127.0.0.1`，Connect，保持佩戴与应用前台运行。第三条命令默认只读：先松开右 Grip，再握紧并移动右手柄，终端显示 `target_m_xyzw`。松开后再次握持会重新建立手柄与机械臂当前 TCP 的参考。`xr_fresh:false` 说明没有新鲜追踪帧，TCP 已连通不等于有追踪数据。

配置中的 XR→机器人基变换是明确的初始约定：XR 右→机器人 +Y、XR 上→机器人 +Z、XR 前（-Z）→机器人 -X（按现场左右、前后均反向而上下正确的反馈，将原映射绕机器人 Z 轴旋转 180°；平移与姿态使用同一个旋转）。首次运动前必须通过预览确认现场朝向；需要改变朝向时修改 `xr_to_robot_basis`，其必须为正交、行列式 +1 的旋转矩阵。

## 真机控制入口（新增预检查尚待现场运动验证）

完成预览方向核对、确认工具/负载、清空运动区域、现场急停就绪后，才使用下列独立入口。按官方要求关闭示教器的同时控制，不要让其他程序并发发指令。本机文件锁只能约束采用同一锁的程序，不能阻止示教器或其他电脑。

```bash
./run.sh realman quest --execute --duration 30
```

该命令允许运动，但不会自动使能机械臂。若控制器未处于可执行状态，应先在现场按厂商流程确认，不能用 ARX 脚本代替。

- 首次新鲜 XR 数据到达后必须松开右 Grip，再握到 >0.8 才开始跟随；持续握持时 0.2–0.8 压力波动不会打断跟随；松开到 <0.2 停止并重新设参考。
- 右 B 退出；Ctrl+C、异常退出、数据超时也尝试发 `set_arm_stop`。退出不回零、不失能、不操作夹爪。
- 默认周期 25 Hz，低跟随 `movep_canfd`；位置缩放 0.3，指令线速度上限 0.02 m/s、角速度上限 0.1 rad/s。
- 目标限制为会话起点周围 5 cm、旋转 0.25 rad；Quest 目标到达会话边界时被限制在边界内，输出 `translation_boundary` / `rotation_boundary`，仍可向范围内移动，不因正常触边退出。后端继续独立拒绝越界目标；候选指令相对当前反馈超前超过 1 cm 或 0.1 rad 时，保持上一条仍在范围内的指令，等待反馈跟上；连续受限满 1 秒，或上一指令本身已超出反馈范围时停止。反馈超时、控制器故障仍立即终止会话。每次重新握持不扩大该会话总边界。
- XR 时间戳缺失/停滞/回退后终止执行会话，需重新启动；独立线程监测命令与反馈 0.3 s 超时。停止发送受 TCP 超时和线程调度影响，并非硬实时保证。

这些是软件目标限制，不是实测末端/关节速度保证，不提供碰撞检测、自动绕开奇异点的路径规划或安全认证；下文的离线预检查只能提前拒绝部分不合适的候选点。网络断开、进程被强杀、主机掉电时无法保证停止命令送达；现场急停与控制器自身保护不可替代。用户已报告一次低跟随真机跟随运动，原版本因会话范围保护退出。用户后续已提供边界/Grip 和短暂滞后处理正常、B 退出正常的运行结果；这不构成完整硬件验收。

## 验证边界与夹爪

针对性测试覆盖协议分帧、单位换算、只读限制、身份核对、速度/边界、Grip 相对参考、XR 时间戳、超时停止及 CLI 预览/执行分支；所有运动测试使用假设备。

真实 `.19` 状态查询通过。用户后续提供的预览结果为 747 次采样、734 次新鲜 XR 帧、548 次目标；随后报告机械臂确实跟随运动，原版本因范围保护退出。以上为用户现场运行结果；本轮修改未再次执行真机运动。

当前按键：右 Grip 按住跟随末端平移和旋转，松开停止；右 B 退出。显式启用 `--gripper` 后，松开 Grip，按住 A 张开、Trigger 闭合，见下文的夹爪说明；左手柄不发送命令。位置缩放 0.3，手移动 1 cm 对应目标约 3 mm；手腕旋转按相对角度映射，仍受范围和速度限制。`armed` 仅表示已完成松手解锁，`following` 表示 Grip 跟随门当前打开，`preview` 决定是否允许运动。

日常持续运行可使用 `./run.sh realman quest --execute --duration 0`，按 B 或 Ctrl+C 结束；首次验证仍建议 `--duration 15`。`--duration 0` 不会自动启动其他服务、使能或回零。命令启动位置作为整个会话的边界中心，不能通过连续松开再握持来扩大；扩大工作空间前需核对现场范围、工具和障碍物。


官方末端工具文档将末端列为选配，并单独指出因时 EG2-4C2 不适用其上述协议；RM65-B 型号或整套交付本身不足以确定夹爪型号。参考 https://develop.realman-robotics.com/robot/json/endeffector/ 。夹爪贴纸 `24V RS485` 不足以识别品牌或协议；仍需交付手册、型号或原控制程序。后端拒绝夹爪目标，不修改工具电压或 RS485 参数。

## 跟随滞后诊断

控制输出的 `command_diagnostics` 包含请求目标、反馈位姿、发送目标、候选位置/角度超前量及 `lead_limited`。位姿单位为 m + xyzw，超前量为 m/rad；发送目标字段表示软件发出的目标，不代表控制器已执行到位。短暂受限不扩大原有 1 cm / 0.1 rad 保护阈值；持续受限 1 秒仍停止。该逻辑已通过假设备回归，用户提供了短暂限幅后恢复跟随并正常退出的现场日志。


## 离线运动学预检查

使用 [RealMan 官方 RM_API2](https://github.com/RealManRobot/RM_API2/tree/a810b9fdea29e3567c5e9155794e6ef9cc17be62) 的 `Algo`，只创建本地算法对象，不创建 `RoboticArm` 网络连接。依赖在 `dependencies.lock.toml` 中固定为 `realman-api`。本机已准备好；其他机器执行：

```bash
./run.sh fetch-dependencies --name realman-api
./run.sh check-dependencies --name realman-api
```

新增只读诊断：

```bash
./run.sh realman check-kinematics
```

它读取控制器实际 DH、关节上下限、当前工具/工作坐标以及当前反馈，设置本地算法数据，然后比较正解与反馈，并对当前 TCP 做逆解。不会发送运动、停止、使能或清错指令。

`--execute` 默认强制启用预检查，缺依赖、版本不一致、当前模型不匹配或姿态接近奇异区时拒绝执行，没有关闭检查的选项。只读 Quest 预览仍只是目标可视化，不代表其所有目标都通过运动学检查。

预检查位于速度/反馈超前限制之后，针对实际发送的量化 JSON 位姿：

- 当前正解与反馈位置偏差不得超过 2 mm、角度偏差不得超过 0.01 rad。
- 逆解必须成功，解必须有限且位于控制器读出的关节限位内，逆解正解残差须在 1 mm / 0.005 rad 内。
- 当前及候选姿态都须通过厂商六轴解析奇异区检查；使用 SDK 默认肘/腕阈值 10°、肩部距离阈值 0.05 m。不会自动降低这些阈值。
- 候选关节解相对上一条成功下发指令的离线关节解，每轴不得改变超过 1°（首次以当前反馈为基准，停止或松开 Grip 后重置），用于拒绝相邻指令的关节突变；累计反馈滞后由原有 1 cm / 0.1 rad 笛卡尔领先限制单独约束；不是实际关节速度保证。失败即拒绝发送该目标并尝试停止。
- 计算结束后再次确认反馈未超时。`command_diagnostics.precheck` 显示逆解关节角、逐轴指令变化、逐轴反馈领先量、最大变化关节编号、残差与奇异区检查结果。

2026-11-02 本机实际只读验证：当前姿态正解位置差约 0.008 mm、姿态差约 0.10°，当前位姿逆解成功、奇异区代码 0。对该采样点的三个平移轴 ±0.5 mm、三个旋转轴 ±0.002 rad 共 12 个本地候选点均通过检查，未发送运动。这里只验证该采样点附近的模型一致性，不能推广为整个工作空间或控制器必然接受所有轨迹。

离线算法版本为 1.6.3-48513146，控制器算法为 1.5.2-0cabec5b，差异保留并显示。控制器仍可能因算法差异、实时状态或其他保护拒绝目标；本地预检查不等于厂商控制器认证，不检测环境碰撞，也不保证插值路径避开所有奇异区域。本轮需先做 15 秒现场小范围测试，再决定是否继续持续运行。

## EG2-4C2 只读诊断

现场已确认型号为因时 EG2-4C2。官方旧版末端工具文档明确上述型号使用控制器内置夹爪指令，并与末端 Modbus 功能互斥；不是 RM_ARM+ 设备信息查询接口。来源：[官方适配文档](https://github.com/RealManRobot/Dev_Center/tree/main/RobotGen3/legacyversions/zh/json)，PDF blob `cf1910b79a039523d3a79da46cd663f3f063f52f`。

在项目根目录执行 `./run.sh realman gripper-status`，仅发送 `get_gripper_state`。不改工具电压、协议开关、串口参数，不发送使能或开合指令。`enable` 是使能标志，`status` 是在线标志；离线时零值不能作为实际力、温度或位置。`actpos` 保留控制器原始开口度数值，不擅自换算毫米。

本次真实只读查询得到 `enable=0, status=0`，其余字段为零；控制器能回答查询，但尚未报告夹爪在线，不能据此判定通信正常。需现场确认夹爪供电、接线及示教器夹爪设备选择；目前 Quest 仍不发送夹爪指令。


## EG2-4C2 开合与 Quest 按键

现场通过示教器松开/闭合已验证可运动，随后查询得到 `enable=1,status=1,error=0,mode=1,temperature=34,actpos=1002`，之前全零不再代表当前状态。采用官方旧版 EG2-4C2 内置命令，无需修改 RM_ARM+ 或 RS485 配置。

项目根目录独立实机测试（先退出遥操，夹爪空载、手远离夹指）：

```bash
./run.sh realman gripper-open --execute
./run.sh realman gripper-status
./run.sh realman gripper-close --execute
./run.sh realman gripper-status
```

两条运动命令应逐条执行并观察；速度固定为100，闭合使用 `set_gripper_pick`、力参数50（协议无量纲，不代表50g或牛顿），不是持续夹取。非阻塞确认只表示接受，不表示完成；待状态变为空闲再发下一条。不设置行程、供电或使能，不自动重试运动。当前未由代码实机验证开合。

独立开合确认后：

```bash
./run.sh realman quest --execute --gripper --duration 30
```

默认不加 `--gripper` 时保持原控制方式。启用时右 Grip 仍只控制机械臂，必须完全松开（<0.2）才能操作夹爪；**按住右A逐段张开，按住右Trigger逐段闭合，松开后不再发下一段**。启动/数据恢复/按过Grip后先松开A与Trigger解锁，同时按两键不发送。

Quest 使用 `set_gripper_position`，每段最多约10/1000原始开口单位（不是毫米），状态查询间隔至少0.15秒。当前段运动中或反馈尚未到达时不发送下一段；换向等待当前段完成后按最新按键方向发下一段，不因正常忙状态退出。遇力控停止后不继续向内夹取，需要松键再操作；单段超过5秒没有完成则报错退出，不自动重试。开口范围按协议1..1000，允许少量反馈端点误差（现场最大1002）。

位置命令没有速度和力字段，**沿用控制器先前设置的速度/力**；本程序不会通过整程开合来隐式设置它们。独立 `gripper-open/close` 仍是整程操作（速度100，夹取力参数50），运动中再次请求返回 `accepted:false`，不当作致命错误。

**松键、B、Ctrl+C、Grip松开及机械臂 `set_arm_stop` 均不保证立即停止夹爪；已接受的小段可能继续完成。** 官方旧版接口没有独立夹爪停止指令，本方案是限制松键后的剩余目标距离，不是即时停止保证。实机需先空载验证位置单位、速度/力继承和分段反馈；当前新行为只经模拟测试，不能宣称真机已通过。

### 关节变化超限的步长缩减

固定笛卡尔速度在不同姿态下会对应不同的关节变化。离线逆解通过模型、关节范围、正逆解残差及奇异区检查，但相邻成功下发关节解变化超过1°时，将本次相对上一条指令的平移和旋转步长一起减半，最多缩减4次（1/16）。每次都检查重新量化后的实际发送位姿；任一次其他检查失败或反馈超时仍终止，五个候选均超限也终止，不扩大阈值、不发送被拒绝的目标。这是离线指令步长约束，不是实际关节速度保证。

诊断 `joint_step_scale` 表示采用比例，`joint_step_rejections` 保存缩减前被拒绝的逐关节差值；例如0.5表示该周期减半。原笛卡尔速度、工作空间与反馈领先限制保留。新行为已通过假设备回归及当前姿态只读模型检查，真实跟随效果仍需现场短测。
