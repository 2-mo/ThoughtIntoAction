# RealMan RM65-BI 平台接入与 Quest 遥操

## 当前平台入口

工作目录为仓库根目录。沿用现有入口，不需要改用独立 RealMan 演示程序：

```bash
./run.sh                           # 原工作台，默认 RealMan 双臂真机待机
./run.sh sim start                 # 同一工作台，RealMan 双臂 Quest 仿真
./run.sh kernel profiles start --profile sim-manual --headless
./run.sh examples sim_control      # 默认 RM65，普通 Robot API 不变
```

已有运行不会因改配置自动重启。先在原工作台停止旧 robot，再按 4 / 5 选择有／无 Quest 的 RealMan 仿真；重新运行 `./run.sh` 更新界面。控制台网页源码的模型已切换到仓库 RM65 URDF／网格，需使用原有网页构建入口更新静态产物。

双臂总控显示当前操作侧，默认左侧；真机对应左 `.19`、右 `.18`。`[` 选左、`]` 选右，原 C/B/X/T/H/J 菜单自动填入该侧 RUN。手机和浏览器控制台在接管时使用同一选择，已取得控制权的会话不自动迁移。总控 `I` 释放／恢复当前侧 Quest 租约，沿用内核现有独占控制规则，不抢占别的输入。原按键 6 仍启动双臂真机手柄待机。

总控 `4` 和 `./run.sh sim start` 使用 `robot-pair --backend sim`：左右各一个 MuJoCo 内核，一个 Quest 进程发布双手输入，工作台网页同屏显示双臂。左 X / 右 A 按住至少 150 ms 后松开切换本侧模式，Grip 相对跟随，Trigger 控制本侧夹爪。总控 `5` 使用 `robot-pair --backend sim --source cli`，同样显示双臂，但不加载 Quest，控制权留给网页 / 动作 / 策略。两个仿真内核独立运行，网页底座为示意布局，不提供双臂之间的物理碰撞；单臂 `sim-manual`、`sim-quest` profile 仍可显式使用。

双臂 Quest 的左 Y／右 B 现用于对应侧回初始位：先松开 Grip、Trigger 与功能键，再单独按住 Y／B 至少 1 秒，继续按住直到到位，松开停止。目标读取本侧 `park_q`，当前仿真与真机配置均为 `[0°, 0°, 90°, 0°, 90°, 0°]`；回位使用既有受限关节目标，夹爪不动。Grip、Trigger、X/A 冲突或输入／控制权失效会取消，需全部松键再操作。B/Y不再触发夹爪初始化；该功能保留独立维护入口。6 项共享输入回归覆盖按住时长、松键、冲突、断流／控制权变化，以及 MuJoCo 实际回位和夹爪开口保持；未执行真机回位。

Quest 输入进程在启动时等待内核满足连续静止反馈条件，再申请控制权；不会因 `runtime.ready` 早于静止窗口而直接退出。已有控制权冲突、内核停止和运行中租约丢失仍报错，不自动抢占或恢复运动。USB/TCP 已连接后，头显仍须唤醒、客户端在前台并发送 Controller 数据；以 VR 面板左右手柄的跟踪状态为准。

同步读取真机反馈后，控制仲裁使用读取完成时的主机时间。不能用周期开始时间判断稍后收到的反馈，否则每帧都会被误判为来自未来，持续清空静止窗口。此修复保留原静止速度、持续时间和反馈超时阈值；使用假设备回归及现场日志离线回放验证，未自动重启或操作真机。

双臂网页按 20 ms 间隔读取反馈，短暂断流保留模型并灰显最后姿态，恢复后继续显示，不因丢帧重载整页。切换运行实例仍重新加载对应模型。Quest 原始手柄帧由输入插件在现有 observer 进程中只读订阅，经标准反馈流送到网页；不另开 SDK，也不从机械臂姿态推断手柄在线。左右手柄分别检查时效，输入过期后撤下按键与位姿数据。

双臂网页的简化夹指复用原夹爪显示组件，分别读取各侧实际／目标开口及该运行声明的最大开口（仿真40 mm，真机名义70 mm）；不把夹爪位置塞入12维机械臂关节向量。未知开口隐藏该侧活动夹指，避免画成虚假的闭合或张开。2026-11-04 用隔离 namespace 下的合成 Trigger，经现有原生协调器、路由、共享输入和 MuJoCo 后端验证了40 mm→接近0→40 mm；5项双臂显示测试及浏览器所用几何函数的0／半开／全开、未知反馈、旧Y轴夹爪回归通过。未执行浏览器视觉验收。同期真机两侧只读反馈仍为夹爪全零、未就绪，这与仿真原先缺少夹指显示是不同问题，不能用显示修复宣称真机夹爪已可用。

## 配置与已确认状态

部署配置：`configs/robots/realman/rm65-19.json`。2026-11-02 对 `192.168.1.19:8080` 的实际只读查询结果：

- 型号 RM65-BI，控制/规划软件 V1.7.0，算法 1.5.2-0cabec5b。
- 系统错误列表 `[0]`。
- 工具 `Lq`，工具坐标 `[0,0,140000,0,0,0]`（Z=140 mm），配置负载 500（0.5 kg），质心配置为零；这不是实测负载或已验证的 TCP 标定。
- 工作坐标系 `Base`，位姿为零。

后端启动时核对型号、工具名/位姿及工作坐标系名/位姿，不写入配置、不清错误、不自动使能。Quest 会话每秒复查当前工具与工作坐标系，变化即退出。`RobotState` 的关节角为 rad，TCP 为 m + xyzw 四元数；未提供的速度和夹爪反馈为 NaN。`mode` 表示本软件控制状态，不代表电机实际上电状态。

`eno1` 需要能直达机械臂网段。当前附加地址 `192.168.1.100/24` 是临时地址，重启失效；没有该地址时，在本机执行 `sudo ip address add 192.168.1.100/24 dev eno1`，不要替换 DHCP 地址或默认路由。平台待机启动遇此类网络错误会保留等待，恢复联网后进入待机，仍需手柄B开始。

如需让本机重启后保留该附加地址，可在本机终端一次性执行下列命令，向当前NetworkManager连接追加地址；保留原DHCP方式、原地址和默认路由。当前地址已由临时命令生效，无需断开/重连网卡，保存后下次激活连接生效：

```bash
sudo nmcli connection modify "Wired connection 1" +ipv4.addresses 192.168.1.100/24
```

该命令会修改主机网络配置，需操作者本机输入sudo密码。仅适用于本机已核对的连接名和网段；不是平台启动时隐式修改网络。

## 只读操作

工作目录 `/home/guest/下载/ThoughtIntoAction-local`：

```bash
./run.sh realman status
./run.sh quest usb prepare --launch-client
./run.sh realman quest --duration 30
```

Quest 中打开 XRoboToolkit，选择头显与 Controller 数据，IP 填 `127.0.0.1`，Connect，保持佩戴与应用前台运行。第三条命令默认只读：先松开右 Grip，再握紧并移动右手柄，终端显示 `target_m_xyzw`。松开后再次握持会重新建立手柄与机械臂当前 TCP 的参考。`xr_fresh:false` 说明没有新鲜追踪帧，TCP 已连通不等于有追踪数据。

配置中的 XR→机器人基变换是明确的初始约定：XR 右→机器人 +Y、XR 上→机器人 +Z、XR 前（-Z）→机器人 -X（按现场左右、前后均反向而上下正确的反馈，将原映射绕机器人 Z 轴旋转 180°；平移与姿态使用同一个旋转）。首次运动前必须通过预览确认现场朝向；需要改变朝向时修改 `xr_to_robot_basis`，其必须为正交、行列式 +1 的旋转矩阵。

## 真机控制入口（新增预检查尚待现场运动验证）

完成预览方向核对、确认工具/负载、清空运动区域、现场急停就绪后，才使用下列独立入口。按官方要求关闭示教器的同时控制，不要让其他程序并发发指令。本机文件锁只能约束采用同一锁的程序，不能阻止示教器或其他电脑。

```bash
./run.sh realman quest --execute --duration 30
```

该命令允许运动，但不会自动使能机械臂。若控制器未处于可执行状态，应先在现场按厂商流程确认，不能用 ARX 脚本代替。

- 首次新鲜 XR 数据到达后必须松开右 Grip，再握到 >0.8 才开始跟随；持续握持时 0.2–0.8 压力波动不会打断跟随；松开到 <0.2 停止并重新设参考。
- 右 B 退出；Ctrl+C、异常退出、数据超时也尝试发 `set_arm_stop`。退出不回零、不失能、不操作夹爪。
- 默认周期 25 Hz，低跟随 `movep_canfd`；位置缩放 1.0，默认配置使用 `speed_percent=50` 和 `linear_speed_percent=100`，按启动时查询的控制器速度计算上限。2026-11-03两台查询均为0.25m/s、0.60rad/s，对应有效上限0.25m/s、0.30rad/s；日志保留百分比、原始上限与计算结果。查询无效则拒绝启动。
- 默认双臂配置 `translation_radius_m=null`、`rotation_radius_rad=null`，关闭平台启动点附近15cm/0.5rad限制；不修改控制器关节限位、奇异区保护或持久速度。需要显式限制时可填写有限正数，映射与后端同时检查。
- 真机采用可反复重定位的相对跟随：每次新握下Grip先清除旧指令，以当时的实际TCP反馈和手柄位置、朝向建立六自由度零位；松开后可自由把手移回舒适位置，再握下不回跳旧目标。握持期间使用逐帧增量跟随：以上一条实际提交的限速目标为基准，手柄本帧增量按1.0缩放，超过周期速度预算的部分丢弃，不积累后续追赶目标。手柄约80ms无有效变化（平移0.3mm/旋转0.002rad噪声门槛），请求停止并清除跟随积压；松Grip立即请求停止。实际物理停止仍有网络和控制器响应延迟。
- 百分比模式下候选指令相对当前反馈超前超过有效速度乘超时时间（当前0.075m、0.09rad）时，保持上一条有效指令；连续受限满1秒或上一指令已超出反馈范围时停止。反馈超时、控制器故障仍立即终止会话。
- XR 时间戳缺失/停滞/回退后，普通执行会话退出，平台待机会话暂停，恢复后需松键并重新按B；独立线程监测命令与反馈 0.3 s 超时。停止发送受 TCP 超时和线程调度影响，并非硬实时保证。

- 当前及候选姿态都须通过厂商六轴解析奇异区检查；使用 SDK 默认肘/腕阈值 10°、肩部距离阈值 0.05 m。不会自动降低这些阈值。

- 计算结束后再次确认反馈未超时。`command_diagnostics.precheck` 显示逆解关节角、逐轴指令变化、逐轴反馈领先量、最大变化关节编号、残差与奇异区检查结果。

`gripper_input.blocked_reason` 显示被拦截的原因：`release_buttons_to_arm` 表示需先松开张开键和Trigger解锁；`conflicting_buttons` 表示两键同时按下；`xr_stale` 表示无新鲜XR数据；`gripper_unavailable` 表示夹爪等待只读恢复。`null` 表示输入没有被互锁拦截，仍需结合 `requested_action` 和后续夹爪反馈判断动作。`arm_following` 表示是否同时在跟随，已取消 `grip_pressed` 拦截。

Quest 使用 `set_gripper_position`，默认每段最多约100/1000原始开口单位（不是毫米），可用 `--gripper-step 5..100` 调整；上一版默认50。状态查询间隔至少0.08秒（上一版0.15）。当前段运动中或反馈尚未到达时不发送下一段；换向等待当前段完成后按最新按键方向发下一段，不因正常忙状态退出。遇力控停止后不继续向内夹取，需要松键再操作；单段超过5秒没有完成则报错退出，不自动重试。开口范围按协议1..1000，允许少量反馈端点误差（现场最大1002）。更大分段减少等待到位反馈的次数，但松键后当前段也可能继续走得更远；100约占原始范围10%，不构成实际距离或立即停止保证。

`--gripper` 启动时先只读检查就绪状态，并按手柄和主机打印原始反馈。启动或操作中收到完整反馈但 `enable!=1`、`status!=1` 或 `error!=0`，暂停夹爪按钮，机械臂仍可在数据和自身状态正常时通过Grip跟随。XR新鲜且对应张开键/Trigger全部松开时，每秒只读复查一次，可以保持Grip跟随；连续两次夹爪在线、使能、无故障且空闲后恢复软件许可，丢弃旧分段调度，必须重新按键才发送下一段。握住夹爪按键不累计恢复次数，恢复期间不发送夹爪运动。日志 `gripper_enabled_for_session` 表示这层软件许可，不表示实时硬件在线。独立开合命令仍拒绝未就绪状态，只有下述显式初始化张开允许全零反馈。TCP超时/断开、反馈缺字段/错误类型、未知模式、开口超范围、命令拒绝及分段5秒超时仍终止会话，不归入此恢复处理。

### 关节变化超限的步长缩减

固定笛卡尔速度在不同姿态下会对应不同的关节变化。离线逆解通过模型、关节范围、正逆解残差及奇异区检查，但相邻成功下发关节解变化超过该轴当前周期预算时，将本次相对上一条指令的平移和旋转步长一起减半，最多缩减4次（1/16）。每次都检查重新量化后的实际发送位姿；反馈超时、模型异常或五个候选均超限仍终止；平台待机模式下，单个候选无逆解或进入厂商奇异区只停止对应侧并清除旧目标，保持Grip不会自动重试；松开该侧Grip再握下，以实际反馈重新归零，另一侧与夹爪继续操作。当前姿态若确实处于奇异区，重新归零不能绕过厂商检查。不发送被拒绝的目标。这是离线指令步长约束，不是实际关节速度保证。

诊断 `joint_step_scale` 表示采用比例，`joint_step_rejections` 保存缩减前被拒绝的逐关节差值；例如0.5表示该周期减半。原笛卡尔速度、工作空间与反馈领先限制保留。新行为已通过假设备回归及当前姿态只读模型检查，真实跟随效果仍需现场短测。

### XR 首帧连接等待

现场独立 SDK 读取观察到启动后6.5秒才出现首帧，之后持续更新；旧执行入口5秒首帧等待会提前终止。现默认等待首帧15秒，可用 `--xr-startup-timeout 30` 指定。等待期间不发送运动，Grip及夹爪按键保持未解锁；首帧到达后仍需松键解锁。已收到数据后的 `stale_s=0.3` 秒断流保护不变，断流不会在原执行会话中自动恢复运动。日志 `waiting_for_first_xr`、`xr_timestamp_ns` 区分连接等待与运行中断流。`--duration` 仍包含启动等待时间，短测建议30秒。
