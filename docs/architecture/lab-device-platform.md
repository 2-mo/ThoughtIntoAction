# 实验室设备接入平台：目标设计

目标是在一台电脑前看见、调用和协同实验室的机械臂、相机、移动机器人与各类传感器。统一工作台承接多模态交互，中央 Agent Harness 组织具身任务，各设备保留独立感知或执行能力，并把实际观测和结果反馈给平台。设计遵循解耦与插件化；它是下一步建设方向，不代表下文所有模块或协议已经实现。

网页的“目标架构”展示这份设计，“实现进展”保留现有计划与 Git 证据。新增目标不借用旧任务的完成率。当前实现及真机验收边界仍以 [overview.md](overview.md) 为准。

## 总体架构与协作边界

目标体验是“一台电脑控制整个实验室”：用户在统一工作台查看设备、视频与任务，通过网页、终端、语音或手势表达目标并接管控制。中央 **Embodied Agent Harness** 根据上下文和环境状态理解任务、选择技能、调用设备能力，再根据真实观测与执行结果继续或结束任务。感知服务、机械臂运动内核和移动机器人运行时分别持有设备连接与本地执行循环。

统一落在设备视图、能力契约、任务状态、控制权和记录入口上。它不要求把厂商 SDK、不同实时循环或所有设备塞进一个进程。相机、传感器、机械臂和移动机器人共享身份与接口规范；一个物理设备可以同时提供感知和执行能力。

主图分为工作台、中央 Agent、感知与执行三个区域，下方是共享平台底座。只画目标/反馈、观测、能力调用/结果及人工接管四条概要连接；完整接口关系在模块详情中展开。区域边界表达职责，不能据此推断所有服务部署在同一台电脑。控制台可以集中运行，设备服务按实际连接、SDK 环境与实时性要求部署在接入主机。

### 中央 Agent Harness

Harness 维护上下文、任务状态、工具执行循环、会话检查点和事件追踪。模型是可替换的推理组件：可以使用 LLM / VLM 做任务规划、使用 VLA 或确定性算法完成特定技能，但模型不直接持有设备 SDK。现有策略入口和脚本任务提供复用基础，中央 Harness、统一场景状态与跨设备技能仍是待建设目标。

中央指统一任务上下文与调用协议的逻辑角色，可按会话或任务隔离运行，不要求整个平台只有一个进程。连续 VLA 策略可以作为受 Harness 监督的独立推理循环，通过控制会话提交带有效期的目标，不逐帧重新调用中央 LLM；设备侧继续执行租约、来源仲裁和本地约束。

上下文包括用户目标、会话记忆、场景引用与设备状态，观测保留时间、坐标系、来源和质量。原始视频按需采样或引用，不无界写入语言模型上下文。技能接口分别表达查询、订阅和动作，返回操作 ID、进度、结果、取消与真实错误；“工具请求受理”不等于“物理动作完成”。

恢复 Agent 检查点时先核对设备状态、任务结果和资源租约。检查点恢复的是计算状态，不能自动重放执行结果不确定的运动。任务编排可以调用子 Agent 或模型插件，但不要求一开始就建立多 Agent 集群。

### 语音、手势与人工接管

语音输入经可替换 ASR 转为文本/候选意图，统一会话将目标交给 Harness，结果可通过 TTS 反馈。语音层管理轮次、打断与音频流；取消播报与取消设备动作使用不同协议。当前定向检查未发现 ASR / TTS 实现，语音明确标为规划接入。

手势既可以表达离散任务，也可以产生连续位姿目标。离散任务进入 Harness，连续目标经控制会话携带来源、租约与短 TTL 直接进入设备运行时，不逐帧经过 LLM。人工接管需要明确暂停任务与转移控制权，不能让两个来源同时写同一执行资源。

现有浏览器手势已在 [teleoperation/runtime.ts](../../apps/console/src/features/teleoperation/runtime.ts) 使用 MediaPipe 手部识别、离合和夹爪映射；[console/kernel/arx.py](../../src/embodied/applications/console/kernel/arx.py) 经 `ControlSession` 提交目标。当前是机械臂适配，通用手势插件和跨设备交互会话尚待补齐。历史设计中的“手势待迁移”不能覆盖较新的源码与 [客户端计划实施记录](../plans/03-kernel-clients.md)。

### 机械臂运动控制核心

机械臂内核单独展开，复用现有 [gateway.py](../../src/embodied/control/gateway.py)、[commands.py](../../src/embodied/control/commands.py) 与 [worker.py](../../src/embodied/control/worker.py)。离散动作可先预览并由 `MotionPlanner` 生成 MoveJ / MoveL / Path 轨迹，再交给调度；连续遥操目标直接进入有界命令路径，不必每次经过轨迹规划。

周期 worker 读取设备状态，通过 `CommandEngine` 执行租约、来源仲裁、轨迹采样和停止/反馈约束，调用驱动并发布 `RobotTick`。只读 observer 对外提供状态，工作台和 Agent 均不接管周期循环。网络请求、语音识别和模型推理不进入这条本地实时路径。新版真机仍待完整验收，原生 Quest 与 RPC 检查路径的差异继续保留在详情中。

移动机器人保留底盘/导航运行时，其他实验装置通过自己的能力插件接入；相机与传感器不需要实现机械臂动作接口。设备身份关联它们的观测与动作，执行结果直接反馈 Agent，不以视觉识别作为动作结束的唯一判据。

### 分工与接口交付

| 协作边界 | 交付内容 |
| --- | --- |
| 多模态工作台 ↔ Harness | 用户目标、来源、会话、进度和回答；人工接管有独立语义 |
| Harness ↔ 技能/工具 ↔ 能力服务 | 类型化输入输出、操作 ID、结果、取消、状态和错误 |
| 能力服务 ↔ 设备目录/控制权 | 解析实例和端点、申请租约、检查权限与有效期；目录不转发实时循环 |
| 感知/执行 → 上下文与实验数据 | 观测、状态和任务事件保留来源；Agent 轨迹与原始实验数据关联但分别维护 |
| 模型/驱动/交互插件 ↔ 装配 | 按契约声明实现、版本、环境和能力，不导入同伴私有实现 |
| 网络/安全/运维 ↔ 服务 | 可替换传输、服务端授权、审计、独立托管与故障清理 |

主图概要连接与详情接口图分别维护：概要用于一屏汇报，详情保留真实对接关系。点击模块可查看职责、相邻模块、现状和 Git 贡献。Git 署名是贡献证据，具体负责人、验收人与交付日期仍由团队明确。

## 层次与职责

| 层次 | 职责 | 依赖边界 |
| --- | --- | --- |
| 网页前端展示 | 浏览器页面、设备面板、可视化、任务进度、交互反馈 | 独立客户端，调用公共应用 API；不持有 SDK、设备连接或业务状态机 |
| 统一终端交互 | CLI / TUI、命令发现、参数输入、状态和日志呈现 | 与网页并列，复用相同业务语义；终端退出不隐式关闭设备 |
| 多模态交互适配 | 语音识别/播报、手势识别、意图与会话、人工接管 | 识别插件与任务语义分开；连续控制不逐帧经过模型 |
| 中央 Agent Harness | 上下文、技能规划、执行循环、工具状态、检查点与追踪 | 不持有设备 SDK，不代替本地实时控制与约束 |
| 应用与实验服务 | 统一 API、请求校验、设备操作、实验编排、任务状态与取消 | 供网页、终端和脚本共同调用；不负责界面绘制或设备实时循环 |
| 公共契约 | 设备身份、能力 schema、状态事件、命令结果、数据流与生命周期 | 小而稳定的协议；不反向依赖应用、实验、具体设备或运行环境 |
| 设备与资源管理 | 实例登记、能力查询、所属主机、连接/健康/占用状态、控制请求 | 通过契约访问设备服务；不复制领域控制循环 |
| 能力运行时 | 机械臂运动、相机流、移动底盘、传感器测量等 | 每类能力独立演进；依赖契约和所选驱动，不依赖工作台 |
| 驱动与协议插件 | 厂商 SDK、设备连接、协议编解码、具体初始化与关闭 | 硬件差异在插件内部；仅在实际复用时提取公共传输插件 |
| 设备与接入主机 | 真实设备、连接设备的计算机、仿真/回放替身 | 实时循环和物理设备所有者靠近设备，平台可跨主机访问服务 |
| 数据、模型与算法 | 观测对齐、存储、质检、导出、推理、规划 | 消费声明的观测或输出能力请求，不直接接管硬件 |
| 网络与通信 | 主机接入、服务端点与路由、连接维护、管理 RPC、事件和观测通道 | 支撑服务间通信；不承担设备语义或自动恢复动作 |
| 安全与权限 | 用户/服务身份、能力级授权、凭据、通信认证、操作审计、设备侧安全职责 | 服务端强制鉴权；设备实时约束在领域运行时执行，不增加远程中心控制循环 |
| 部署与运维 | 配置、依赖环境、进程托管、健康、日志、指标和时间质量 | 服务不依赖某个网页或终端存活；凭据以引用传递，不混入公开配置 |

机器人内核是“机械臂能力运行时”，不再承担整个实验室的通用设备内核职责。相机、底盘和传感器不进入机械臂 `worker`，不必实现 `RobotBackend.step(ControlCommand)`。

公共契约是共享接口与 schema，不拥有设备、不转发请求，也不额外建立中心进程。主图箭头表示主要交互，模块详情分别说明已有基础与待建设内容；主图中的分组和连线不表示全部能力已经实现。

网络、安全和运维是横向支撑各服务的基础设施，在图中单独分组，不是所有设备请求依次穿过的串行中转层。插件治理管理实现和装配，与这些基础设施分别维护职责。

## 网页、终端与公共应用服务

网页和终端需要分别维护。网页面向设备视图、可视化与任务交互；终端面向命令、参数、脚本自动化与文字状态。两者都调用公共应用服务，实验步骤、动作语义、设备状态机和取消逻辑只维护一份。

```text
网页前端 ── API 客户端 ─┐
                       ├─ 应用服务 ─ 设备管理 / 实验编排 ─ 能力运行时 ─ 驱动
CLI / TUI ─ 命令适配 ──┘        │                          │
                         服务端身份与权限检查        租约 + 设备侧约束
```

视图插件负责呈现和交互，命令插件负责参数解析和输出，业务插件负责实验与操作。它们共享契约，不互相导入私有实现。新增一种设备能力时可增加相应视图和命令适配，不在两个入口里各写一套执行逻辑。

终端可以显式请求启动、停止或重启服务，但进程托管与设备生命周期属于应用/运维服务。关闭窗口或刷新网页不代表停止设备，也不能让设备失去唯一所有者。前端隐藏按钮或终端参数校验不能替代服务端权限检查。

当前已有独立 Vue 控制台、监看页和 `./run.sh` / tmux / Rich 终端；其业务入口和部分进程装配仍需按上述边界继续收敛。本设计没有把它们描述成已经完成实验室级统一入口。

## 网络、安全与运维基础设施

### 网络与通信层

网络接入明确主机、监听地址、受控入口及连接质量；服务定位负责将已登记能力解析为端点；传输插件负责管理请求、状态事件与大流量数据。设备实例目录回答“是什么设备、归属哪里”，服务端点目录回答“从哪里访问”，插件目录回答“用哪个实现”，三者不能混为一张注册表。

网络传输与硬件协议也分别维护。即使某个设备通过网络连接，厂商协议解码、初始化和动作语义仍归驱动；网络层只负责连接和消息传输。网络恢复不自动取得控制权，也不能无条件重发运动命令。

现有基础包括本机 Unix socket RPC、控制台 Tailscale / LAN 部署、HTTPS 与 WebRTC 等通道。它们是局部实现，尚未构成通用多主机服务发现、路由或网络治理。平台不要求所有设备绑定一种远程协议。

### 安全与权限层

| 职责 | 回答的问题 | 执行位置与边界 |
| --- | --- | --- |
| 身份与权限 | 谁可以查询、订阅或控制哪些能力？ | API 及实际受保护服务端强制检查，不能只放在网页或终端 |
| 资源占用与租约 | 此刻谁拥有这个资源？ | 资源所有者与对应能力运行时；租约不替代身份权限 |
| 设备侧安全约束 | 当前反馈与约束下，这个动作能否执行？ | 设备侧运行时的限位、输出许可、有效期与停止逻辑；权限和租约均不能绕过 |
| 凭据与审计 | 如何建立认证通信，如何追溯实际操作？ | 凭据提供方、服务与审计输出；保留身份、目标、请求 ID、授权与执行结果 |

身份提供方、授权策略、凭据提供方和审计输出可按接口扩展，但强制校验位置不能变成可随意关闭的插件选项。设备安全策略按能力适配，最终执行仍在本地运行时，不依赖一次远程网络调用才能限制危险输出。软件停止与硬件急停分别设计、分别验收。

控制台已有配对令牌、本地证书与加密通信基础；统一用户/服务身份、能力级授权、凭据生命周期、操作审计及跨设备安全约束仍待建设。Git 贡献记录只反映代码变更，不能冒充设备操作审计或安全验收。原生 Quest 与 RPC 的工作区检查差异继续如实保留。

### 部署配置与可观测性

部署、环境与进程监督独立于两个交互入口；实例配置、运行环境与凭据引用分别管理。每个服务报告健康、日志、指标、错误及时间基准质量，由运维能力汇聚。时间同步只能提供带质量信息的基准，不能把网络连通视为时钟已同步。

复用现有工作台与环境管理，逐步把托管语义从终端呈现中分离。故障、取消和退出路径保留真实结果，并清理已创建的设备、连接和资源；不能因某个面板退出而失去这些职责。

## 插件化与解耦规则

1. **接口与实现分开。** 公共契约定义可观察行为，插件负责实现；应用按能力使用设备，不以型号名称决定调用链。
2. **插件与实例分开。** 插件目录记录实现、入口、版本与环境；设备目录记录实验室实际设备。同一个插件可以建立多个设备实例，每个实例各自拥有身份、连接、状态与资源。
3. **共享基础，保留专业接口。** 所有设备共享描述与基础生命周期；动作、图像流、底盘运动、测量等按能力定义类型化接口。只读传感器没有动作方法也能接入。
4. **能力允许组合。** RGB-D 相机可以同时提供 RGB、深度、内参与 IMU；移动机器人可以组合底盘、定位和相机能力。设备类别用于导航，不能替代能力检查。
5. **装配集中。** 配置选择实例、插件、运行环境及服务端点；使用现有 Registry 演进，不再平行增加第二套工厂注册表。
6. **插件不等于微服务。** 只有设备独占、SDK 依赖冲突、实时性或故障隔离需要时才增加进程。纯算法与格式转换可保留为库插件。
7. **插件不依赖具体同伴。** 通过契约声明所需能力，在装配时解析；禁止直接导入另一个设备插件的私有实现。算法不反向导入实验组织代码。
8. **加载、连接、使能分开。** 查询插件目录或验证配置不打开设备；设备上线不取得控制权；重新连接不自动恢复动作或重放旧命令。
9. **交互入口与业务分开。** 网页、CLI / TUI 是不同客户端，共享应用服务与实验逻辑；设备进程生命周期不依赖界面窗口。
10. **基础设施与强制规则分开。** 网络、认证、审计和运维实现可扩展；实际受保护能力的权限检查、资源互斥与设备约束不能通过更换插件绕过。

插件类型按真实扩展点逐步增加：设备驱动、能力适配、传输、算法/模型、实验步骤、采集/导出、界面视图。当前并非每一类都有可用工厂，不为没有实际需求的类型登记空实现，也不预设热更新或远程安装机制。

## 最小公共契约

### 设备实例与插件声明

| 对象 | 最小字段或语义 |
| --- | --- |
| 插件声明 | `plugin_id`、种类、实现入口、插件版本、契约版本、运行环境、依赖、提供的能力 |
| 设备实例 | `device_id`、名称、类别、`driver_id`、驱动版本、`host_id`、位置、连接配置引用、能力列表、流列表、资源标识 |
| 能力描述 | `capability_id`、版本、输入输出 schema、单位、坐标系、约束、是否改变设备状态、取消与超时语义 |
| 服务定位 | 实例/能力到服务端点的映射，以及所属主机和更新时间；具体传输由部署选择 |
| 配置边界 | 型号参数由驱动解释，连接地址和秘密留在部署配置；公开描述只携带必要引用 |

`device_id` 标识设备实例，不能用易变端口或插件名称代替。插件版本与能力契约版本分别记录。具体驱动仅实现它声明支持的能力，消费者在实验开始前检查兼容性。

### 生命周期与状态

基础生命周期表达“描述 → 显式连接 → 健康检查 → 关闭”；发现是可选插件能力，先实现人工登记，再增加实际协议支持的发现方式。

状态分别表达：是否登记、连接阶段、健康/故障、观测是否新鲜、资源是否被占用、调用者是否持有控制权。每类状态附更新时间与错误原因。进程存在、端口连通、设备出数据和可执行动作不能互相替代。

设备服务拥有连接并负责失败清理。一个实例连接失败不应拖垮其他设备；关闭失败保留真实错误。重连可恢复观测，但恢复输出需要重新满足许可、租约和领域运行时条件。

### 命令、状态事件与数据流

| 通道 | 内容与规则 |
| --- | --- |
| 管理与控制 | 查询描述、连接管理、申请/释放资源、能力命令、取消；携带来源、请求 ID、租约/有效期、状态与错误 |
| 状态与事件 | 连接变化、故障、控制权变化、操作完成/失败；区分请求已受理与实际执行完成 |
| 观测数据 | 图像、遥测、测量；携带设备/流 ID、序号、采样时间、接收时间、时间基准、单位、坐标系、质量与缺失信息 |

控制面不转发所有大流量数据；相机和时序流可使用适合自身吞吐的传输。平台不在此阶段规定所有设备必须走 ROS、某个消息总线或单一网络协议。

机械臂或底盘的实时执行与最后一道约束检查留在设备侧运行时。网络请求只提交有期限的目标或动作，不用网络心跳替代实时控制循环。数据消费者不能通过订阅接口取得执行权。

## 设备接入细节

下面四类设备用于明确接入与验收范围，主图仍按感知和执行能力组织。机械臂状态与移动机器人里程计可以参与状态估计，但动作完成、失败和故障反馈仍由执行运行时直接上报。

| 设备 | 主要能力 | 需要单独验证的部分 |
| --- | --- | --- |
| 机械臂 | 状态反馈、关节/笛卡尔动作、夹爪、停止；按设备声明可选能力 | 关节数、单位、运动学、限位、停止与断连行为；现有 X5 新版真机内核仍待完整验收 |
| 相机 | RGB/深度等帧、内参、时间戳、按需曝光与触发 | 帧格式、丢帧、同步、设备独占、多个订阅者；已有 RealSense / synthetic 基础 |
| 移动机器人 | 底盘速度/目标、里程计；可选定位、导航与停止 | 坐标系、速度约束、导航取消、断连停车、定位质量；型号和适配协议尚待选择 |
| 传感器 | 标量/向量/时序观测、事件；可选采样配置、触发或校准 | 单位、量程、采样时间、有效性、延迟和校准来源；需要选定真实设备验证 |

Quest、iPhone 等作为控制输入插件，可以映射到支持的能力；输入设备不拥有目标设备 SDK。机械臂的原生 Quest 路径与 RPC 路径保留其真实约束差异，不把现有行为写成所有设备已统一通过相同检查。

## 资源与实验编排

相机可以由一个服务持有设备、多个消费者共享读取；机械臂和底盘输出按实际资源互斥。当前 `DeviceLease` 是本机文件锁，机器人租约也有自身范围，不能直接当作分布式设备调度。

通用实验步骤声明所需能力和资源，由装配层选择设备实例。执行前检查能力兼容性与必要状态，按确定顺序申请资源，申请失败释放已获得资源；执行中记录部分成功、失败、取消与关闭结果。多设备步骤不承诺物理动作可以原子回滚。

跨主机扩展时，需另行实现服务认证、租约有效期和撤权、重复请求处理、连接中断的本地停止规则。状态汇聚不能代替接入主机的实际资源所有权。多机时间对齐应记录时钟来源与误差，不把软件时间戳宣称为硬件同步。

## 现有基础与缺口

| 现有基础 | 可以复用 | 尚缺的实验室能力 |
| --- | --- | --- |
| `contracts/registry.py` | 显式工厂、按需加载、运行环境与 API 版本检查 | 通用插件声明演进；设备实例目录不在此类职责内 |
| `contracts/interfaces.py` | 机器人、相机、输入、规划等专业接口 | 跨设备身份、能力 schema 与状态/生命周期契约 |
| `control/`、`devices/robots/` | 机械臂运行时、驱动、模型与仿真 | 新设备类别各自的运行时，非通用化当前 worker |
| `devices/sensors/` | 独立相机所有者、共享帧与工厂 | 通用传感器测量、事件和设备协议适配 |
| `applications/workstation/` | 本机服务装配与现有工作台 | 多设备实例展示、服务定位、多主机管理 |
| `apps/console/`、`applications/console/` | 独立网页、版本化 API、局部配对令牌/HTTPS/WebRTC | 统一应用服务、能力级授权、实验室通用前端与网络治理 |
| `apps/console/src/features/teleoperation/` | 浏览器手势、离合、夹爪映射与短 TTL 控制接入 | 通用手势插件、跨模态交互会话；语音 ASR / TTS 尚待建设 |
| `run.sh`、工作台终端 | CLI / TUI、命令发现、状态与日志入口 | 命令适配与托管解耦，和网页共享完整业务语义 |
| `data/`、`policy/` | 采集、导出、策略环境与适配基础 | 移动机器人/新传感器 schema、通用实验来源与能力适配 |
| 现有操作、任务与策略入口 | 可作为 Harness 调用的技能基础 | 中央 Agent、场景上下文、工具目录、会话检查点与恢复 |

旧执行入口与迁移中的生命周期保持如实标注；本设计不删除旧链路，也不改变真机动作。

## 推进顺序与验收依据

1. **入口与公共服务解耦。** 明确网页、终端、应用服务、托管和现有网络/访问控制的职责。验证同一操作在两种入口使用相同语义，刷新页面或退出终端不会重启设备。
2. **设备目录、能力与生命周期。** 登记现有 X5、RealSense、Quest、iPhone 与仿真，补齐共享描述和能力 schema。验证同驱动多实例、状态过期、相机多订阅、控制互斥、失败清理和取消；查询目录不得连接或使能设备。
3. **网络、安全与运维基础。** 补齐服务定位、能力权限、凭据审计、独立托管和诊断，验证失联、权限撤销、租约过期、部分失败及重连不恢复旧动作。单机规则通过后再扩展多主机。
4. **中央 Harness 与已有能力闭环。** 从查询状态、订阅观测和一个可取消的仿真技能开始，接入上下文、工具调用与真实结果记录。验证受理/完成区分、取消、失败、检查点恢复和人工接管，再扩大技能范围。
5. **多模态入口与新设备协同。** 将已有手势能力按统一会话收敛，增设语音识别/播报适配；选择一台移动机器人和一种传感器逐项接入。验证连续目标不逐帧经过 LLM、多设备资源协调和完整实验记录，不必修改其他设备 worker 或复制应用逻辑。

具体型号、协议、物理资源关系和验证场景在接入前确认。本轮只完善设计与可视化，不据此声称已经完成新硬件接入或现场验证。
