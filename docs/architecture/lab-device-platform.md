# 实验室设备接入平台：目标设计

目标是把实验室的机械臂、相机、移动机器人和各类传感器接入同一平台，让设备可以被发现或登记、查看状态、按能力使用，并组合成可记录的实验。设计遵循解耦与插件化；它是下一步建设方向，不代表下文所有模块或协议已经实现。

网页的“目标架构”展示这份设计，“实现进展”保留现有计划与 Git 证据。新增目标不借用旧任务的完成率。当前实现及真机验收边界仍以 [overview.md](overview.md) 为准。

## 层次与职责

| 层次 | 职责 | 依赖边界 |
| --- | --- | --- |
| 应用与实验 | 实验室工作台、设备面板、采集、遥操、标定、实验步骤 | 使用设备描述、能力客户端与数据订阅；不导入厂商 SDK |
| 公共契约 | 设备身份、能力 schema、状态事件、命令结果、数据流与生命周期 | 小而稳定的协议；不反向依赖应用、实验、具体设备或运行环境 |
| 设备与资源管理 | 实例登记、能力查询、所属主机、连接/健康/占用状态、控制请求 | 通过契约访问设备服务；不复制领域控制循环 |
| 能力运行时 | 机械臂运动、相机流、移动底盘、传感器测量等 | 每类能力独立演进；依赖契约和所选驱动，不依赖工作台 |
| 驱动与协议插件 | 厂商 SDK、设备连接、协议编解码、具体初始化与关闭 | 硬件差异在插件内部；仅在实际复用时提取公共传输插件 |
| 设备与接入主机 | 真实设备、连接设备的计算机、仿真/回放替身 | 实时循环和物理设备所有者靠近设备，平台可跨主机访问服务 |
| 数据、模型与算法 | 观测对齐、存储、质检、导出、推理、规划 | 消费声明的观测或输出能力请求，不直接接管硬件 |

机器人内核是“机械臂能力运行时”，不再承担整个实验室的通用设备内核职责。相机、底盘和传感器不进入机械臂 `worker`，不必实现 `RobotBackend.step(ControlCommand)`。

公共契约是共享接口与 schema，不拥有设备、不转发请求，也不额外建立中心进程。图中的虚线连线表示契约依赖，实线表示主要交互；虚线模块边框表示待建设，两者含义分别说明。

## 插件化与解耦规则

1. **接口与实现分开。** 公共契约定义可观察行为，插件负责实现；应用按能力使用设备，不以型号名称决定调用链。
2. **插件与实例分开。** 插件目录记录实现、入口、版本与环境；设备目录记录实验室实际设备。同一个插件可以建立多个设备实例，每个实例各自拥有身份、连接、状态与资源。
3. **共享基础，保留专业接口。** 所有设备共享描述与基础生命周期；动作、图像流、底盘运动、测量等按能力定义类型化接口。只读传感器没有动作方法也能接入。
4. **能力允许组合。** RGB-D 相机可以同时提供 RGB、深度、内参与 IMU；移动机器人可以组合底盘、定位和相机能力。设备类别用于导航，不能替代能力检查。
5. **装配集中。** 配置选择实例、插件、运行环境及服务端点；使用现有 Registry 演进，不再平行增加第二套工厂注册表。
6. **插件不等于微服务。** 只有设备独占、SDK 依赖冲突、实时性或故障隔离需要时才增加进程。纯算法与格式转换可保留为库插件。
7. **插件不依赖具体同伴。** 通过契约声明所需能力，在装配时解析；禁止直接导入另一个设备插件的私有实现。算法不反向导入实验组织代码。
8. **加载、连接、使能分开。** 查询插件目录或验证配置不打开设备；设备上线不取得控制权；重新连接不自动恢复动作或重放旧命令。

插件类型按真实扩展点逐步增加：设备驱动、能力适配、传输、算法/模型、实验步骤、采集/导出、界面视图。当前并非每一类都有可用工厂，不为没有实际需求的类型登记空实现，也不预设热更新或远程安装机制。

## 最小公共契约

### 设备实例与插件声明

| 对象 | 最小字段或语义 |
| --- | --- |
| 插件声明 | `plugin_id`、种类、实现入口、插件版本、契约版本、运行环境、依赖、提供的能力 |
| 设备实例 | `device_id`、名称、类别、`driver_id`、驱动版本、`host_id`、位置、连接配置引用、能力列表、流列表、资源标识 |
| 能力描述 | `capability_id`、版本、输入输出 schema、单位、坐标系、约束、是否改变设备状态、取消与超时语义 |
| 服务定位 | 实例/能力到服务端点的映射，以及所属主机和更新时间；具体传输由部署选择 |
| 配置边界 | 型号参数由驱动解释，连接地址和秘密留在部署配置；公开描述只携带必要引用 |

`device_id` 标识设备实例，不能用易变端口或插件名称代替。插件版本与能力契约版本分别记录。具体驱动仅实现它声明支持的能力，消费者在实验开始前检查兼容性。

### 生命周期与状态

基础生命周期表达“描述 → 显式连接 → 健康检查 → 关闭”；发现是可选插件能力，先实现人工登记，再增加实际协议支持的发现方式。

状态分别表达：是否登记、连接阶段、健康/故障、观测是否新鲜、资源是否被占用、调用者是否持有控制权。每类状态附更新时间与错误原因。进程存在、端口连通、设备出数据和可执行动作不能互相替代。

设备服务拥有连接并负责失败清理。一个实例连接失败不应拖垮其他设备；关闭失败保留真实错误。重连可恢复观测，但恢复输出需要重新满足许可、租约和领域运行时条件。

### 命令、状态事件与数据流

| 通道 | 内容与规则 |
| --- | --- |
| 管理与控制 | 查询描述、连接管理、申请/释放资源、能力命令、取消；携带来源、请求 ID、租约/有效期、状态与错误 |
| 状态与事件 | 连接变化、故障、控制权变化、操作完成/失败；区分请求已受理与实际执行完成 |
| 观测数据 | 图像、遥测、测量；携带设备/流 ID、序号、采样时间、接收时间、时间基准、单位、坐标系、质量与缺失信息 |

控制面不转发所有大流量数据；相机和时序流可使用适合自身吞吐的传输。平台不在此阶段规定所有设备必须走 ROS、某个消息总线或单一网络协议。

机械臂或底盘的实时执行与最后一道约束检查留在设备侧运行时。网络请求只提交有期限的目标或动作，不用网络心跳替代实时控制循环。数据消费者不能通过订阅接口取得执行权。

## 四类设备的能力边界

| 设备 | 主要能力 | 需要单独验证的部分 |
| --- | --- | --- |
| 机械臂 | 状态反馈、关节/笛卡尔动作、夹爪、停止；按设备声明可选能力 | 关节数、单位、运动学、限位、停止与断连行为；现有 X5 新版真机内核仍待完整验收 |
| 相机 | RGB/深度等帧、内参、时间戳、按需曝光与触发 | 帧格式、丢帧、同步、设备独占、多个订阅者；已有 RealSense / synthetic 基础 |
| 移动机器人 | 底盘速度/目标、里程计；可选定位、导航与停止 | 坐标系、速度约束、导航取消、断连停车、定位质量；型号和适配协议尚待选择 |
| 传感器 | 标量/向量/时序观测、事件；可选采样配置、触发或校准 | 单位、量程、采样时间、有效性、延迟和校准来源；需要选定真实设备验证 |

Quest、iPhone 等作为控制输入插件，可以映射到支持的能力；输入设备不拥有目标设备 SDK。机械臂的原生 Quest 路径与 RPC 路径保留其真实约束差异，不把现有行为写成所有设备已统一通过相同检查。

## 资源与实验编排

相机可以由一个服务持有设备、多个消费者共享读取；机械臂和底盘输出按实际资源互斥。当前 `DeviceLease` 是本机文件锁，机器人租约也有自身范围，不能直接当作分布式设备调度。

通用实验步骤声明所需能力和资源，由装配层选择设备实例。执行前检查能力兼容性与必要状态，按确定顺序申请资源，申请失败释放已获得资源；执行中记录部分成功、失败、取消与关闭结果。多设备步骤不承诺物理动作可以原子回滚。

跨主机扩展时，需另行实现服务认证、租约有效期和撤权、重复请求处理、连接中断的本地停止规则。状态汇聚不能代替接入主机的实际资源所有权。多机时间对齐应记录时钟来源与误差，不把软件时间戳宣称为硬件同步。

## 现有基础与缺口

| 现有基础 | 可以复用 | 尚缺的实验室能力 |
| --- | --- | --- |
| `contracts/registry.py` | 显式工厂、按需加载、运行环境与 API 版本检查 | 通用插件声明演进；设备实例目录不在此类职责内 |
| `contracts/interfaces.py` | 机器人、相机、输入、规划等专业接口 | 跨设备身份、能力 schema 与状态/生命周期契约 |
| `control/`、`devices/robots/` | 机械臂运行时、驱动、模型与仿真 | 新设备类别各自的运行时，非通用化当前 worker |
| `devices/sensors/` | 独立相机所有者、共享帧与工厂 | 通用传感器测量、事件和设备协议适配 |
| `applications/workstation/` | 本机服务装配与现有工作台 | 多设备实例展示、服务定位、多主机管理 |
| `data/`、`policy/` | 采集、导出、策略环境与适配基础 | 移动机器人/新传感器 schema、通用实验来源与能力适配 |

旧执行入口与迁移中的生命周期保持如实标注；本设计不删除旧链路，也不改变真机动作。

## 推进顺序与验收依据

1. **设备实例和只读状态。** 先登记现有 X5、RealSense、Quest、iPhone 与仿真。验证同一插件多实例、稳定身份、所属主机、能力查询和状态过期。查询目录不得连接或使能设备。
2. **能力与生命周期。** 复用现有服务，补齐共享描述与能力 schema。验证相机多订阅、控制互斥、连接失败清理、取消、撤权及重连不恢复旧动作。
3. **新类别接入。** 选择一台真实移动机器人和一种真实传感器。新增实现应限于驱动/适配、必要能力运行时、配置与对应数据视图；无需修改已有机械臂 worker、数据主流程或工作台中的型号分支。
4. **多主机与实验编排。** 在单主机契约通过后引入主机登记、服务定位、认证与资源协调，验证主机失联、部分失败、取消和完整实验记录。

具体型号、协议、物理资源关系和验证场景在接入前确认。本轮只完善设计与可视化，不据此声称已经完成新硬件接入或现场验证。
