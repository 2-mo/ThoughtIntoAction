Next architecture steps

下一步，收拢维护边界。

建议先统一入口和接口，再整理目录。保留 arx 已经清晰的 VR、路由、控制器和设备边界。

建议 · 尚未实施
代码已集中到一个仓库。当前最值得整理的是：多个执行入口、两个近似的标定包名，以及按原项目命名的功能包。
P0

明确推荐入口与兼容入口

以 workbench / components 作为导航主线，旧 presets、脚本和历史页面标注所属流程。默认启动行为的改变单独验收。

验收：每个入口都能说明执行后端与控制权归属。
P1

把自动操作接到公共执行接口

逐个适配网页控制、双相机自动标定、方块任务、GR00T 执行。保留各自算法；执行端统一处理申请、提交、取消、超时和状态。

验收：同一任务可对仿真后端运行，再接真机。
P1

按功能域收拢包名与配置

两个手眼包先分清 workflow、solver、device adapter，再合到明确命名空间。轨迹、运动学、模型、相机配置分别归其所属部件。

验收：改一个功能，无需在多个原项目目录间找实现。
P2

让插件带着契约与验收走

为每个部件标明工厂、环境、输入输出、单位、状态所有权和离线检查。B601 的轴数与模型需要独立协议适配，再接共享工作台。

验收：单部件可替换、可验证，组合行为仍有测试。

建议的功能视图

这是后续归类方向；下列功能域不代表已经存在同名目录。

QuestArmTeleop/
├─ control/          arx 控制内核
├─ src/
│  ├─ inputs         VR / 手机 / 回放
│  ├─ devices        机械臂 / 相机适配

│  ├─ collection     观测 / 采集 / 封存
│  ├─ datasets       校验 / 导出 / 统计
│  ├─ policies       模型 / 动作适配

├─ apps/             网页 / iOS
├─ configs/          插件 / 组合 / 设备
├─ assets/           模型 / 网格
└─ archives/         恢复副本
