# 基于手部姿态的 ARX5 实时遥操作设计

- 日期：2026-07-27
- 状态：设计已确认
- 目标硬件：ARX X5、MacBook Pro M3 Max、机械臂主机、Intel RealSense D455

## 1. 目标

在现有网页控制台中增加手势遥操作：Mac 内置摄像头在浏览器本地运行
MediaPipe Hand Landmarker，机械臂以相对 6DoF 跟随控制手，另一只手作为
“按住才动”的离合，控制手的捏合状态控制夹爪开闭。

第一版优先达到以下结果：

- Mac 浏览器稳定处理约 30 FPS，目标链路延迟低于 100 ms。
- 机械臂位置与手掌朝向连续跟随，无明显跳变。
- 精细、快速两档可切换。
- 捏合关闭夹爪、松开张开夹爪，关闭使用限扭矩控制。
- 具备安全盒、软边界、限速、IK、碰撞检查、watchdog 和反馈故障保护。

延迟目标用于页面实时观察，不作为第一版长时间统计门禁。滤波、增益和阈值均
保留配置入口，后续根据录制轨迹和真机感受继续调整。

## 2. 现有基础

项目已有以下可复用能力：

- D455 RGB-D 通过 WebRTC 送到 Mac 浏览器，D455 继续用于观察机器人工作区。
- 浏览器已集成本地 MediaPipe Pose Landmarker 和双手 Hand Landmarker 模型。
- 控制服务已有配对令牌、单客户端控制权、CAN 文件锁和网页急停。
- `CartesianServo` 和 `GripperServo` 已提供 100 Hz、Ruckig、200 ms watchdog、
  反馈停滞和故障阻尼保护。
- 笛卡尔规划已有 IK、关节限位、奇异点降速、自碰撞和配置障碍物检查。

当前两个实时伺服互斥，笛卡尔伺服仅处理 XYZ 且夹爪位置固定。新功能需要一条
统一伺服，在同一个控制周期内发送机械臂和夹爪命令。

## 3. 范围

### 3.1 包含

- Mac 浏览器 `getUserMedia()` 摄像头输入和授权状态。
- 双手 Hand Landmarker、手掌姿态、离合手势和捏合状态。
- 相对 6DoF 映射、滤波、死区、单帧步长限制和双档速度配置。
- 遥操作 WebSocket 协议和服务端会话独占。
- 同时控制六关节与夹爪的 `TeleoperationServo`。
- TCP 安全盒、最低高度、软边界和现有运动安全检查。
- 与手眼标定共用视觉工具区域的切换界面。
- 最小自动测试、只读验证、3D Ghost 验证和分阶段真机验收。

### 3.2 不包含

- 将手在相机中的绝对位置映射到机器人基座。
- Mac 摄像头的米制深度或高精度 Z 测量。
- 动态人体/障碍物检测和自动生成工作空间。
- 人体关节角到机器人关节角的直接模仿。
- 训练自定义手势模型。
- 物理急停集成。网页急停和直接断电不能替代独立物理急停。

## 4. 总体架构

```text
Mac 内置摄像头 getUserMedia
        ↓
浏览器 Hand Landmarker，双手 30 FPS，只处理最新帧
  控制手：相对 X/Y、掌部尺度 Z、手掌 quaternion、捏合状态
  离合手：张掌启停
        ↓
TeleopMapper：相对 6DoF、滤波、死区、双档增益
        ↓
加密控制 WebSocket：teleop start/update/stop
        ↓
服务端 TeleoperationServo，100 Hz
  协议校验 → 安全盒 → IK/奇异点/碰撞 → Ruckig
        ↓
单条 command_joint_servo 同时发送关节和夹爪目标
```

浏览器只表达操作意图。所有最终边界、运动限制和故障处理由服务端执行，前端
不能通过修改增益、速度百分比或目标值绕过安全配置。

## 5. 浏览器手部估计

### 5.1 摄像头

手势页通过 `navigator.mediaDevices.getUserMedia()` 请求：

```text
video.width  ideal 1280
video.height ideal 720
video.frameRate ideal 30, max 30
video.facingMode user
audio false
```

页面运行在现有 HTTPS 环境中。首次使用由用户明确授予 macOS/Chrome 摄像头权限；
权限拒绝或设备不可用时不能启用遥操作。

Mac 预览使用 CSS 镜像，方便操作者观察。计算使用明确的“操作者坐标”：镜像后
画面向右、画面向上、手远离摄像头分别为正方向。显示镜像不会改变 MediaPipe
输入图像；代码统一转换坐标和 handedness，防止左右控制反转。

### 5.2 推理调度

- 遥操作时只运行 Hand Landmarker，配置 `numHands: 2`；Pose Landmarker 暂停。
- 使用 `requestVideoFrameCallback()` 驱动，最多 30 FPS。
- 推理未完成时不提交下一帧，任何时候最多保留一个待处理帧。
- 控制手默认右手，网页可切换左手；另一只手自动成为离合手。
- 两只手的 handedness 分数均须不低于 0.70。

### 5.3 手掌姿态

手掌姿态使用控制手的 world landmarks：腕点 0、食指 MCP 5、中指 MCP 9、
小指 MCP 17。食指到小指方向、腕到中指方向和二者叉积建立正交坐标系；根据
handedness 使用固定符号归一化，使左右控制手做相同动作时产生相同旋转方向。

每个 quaternion 均归一化。若它与上一帧 quaternion 点积为负，则整体取反，
保证四元数符号连续。手掌坐标系退化、关键点非有限或置信度不足时，该帧无效。

### 5.4 相对平移

掌部尺度 `s` 取以下归一化图像距离的中值：0-5、0-17、5-17、0-9。离合接通
时保存腕点 `(u0, v0)` 和 `s0`。操作者坐标中的原始位移为：

```text
away_m  = 0.25 * ln(s0 / s)
right_m = 0.40 * (u - u0)
up_m    = 0.40 * (v0 - v)
```

默认操作者坐标到机器人基座坐标映射为：

```text
手远离摄像头  → base +X
画面向右      → base -Y
画面向上      → base +Z
```

映射矩阵保存在服务端遥操作配置中，并以只读形式发给浏览器；可修改符号和轴排列，
但必须是正交的有符号置换矩阵。修改后先通过 3D Ghost 验证，配置才可用于真机。

Mac 单目摄像头的 Z 只表示相对掌部尺度变化，不提供米制绝对深度。强滤波、死区、
单帧最大步长和服务端速度上限共同限制其误差。

### 5.5 相对旋转

离合接通时保存手掌 quaternion 和机器人当前 TCP quaternion。每帧计算手掌相对
旋转，将其从操作者坐标变换到基座坐标，再按档位旋转增益从单位 quaternion
做 SLERP。结果左乘离合起点的 TCP quaternion，得到本次目标姿态。

## 6. 手势状态机

### 6.1 离合

离合手的食指、中指、无名指、小指均伸直即为张掌；每根手指的 MCP-PIP-DIP
三点夹角须不小于 155 度，拇指不参与判定。

- 张掌连续 5 个有效帧后接通，约 150-170 ms。
- 非张掌连续 2 帧、离合手丢失或数据超过 100 ms 后断开。
- 接通瞬间同时记录手部零点和服务端 TCP 起点，不发送位移跳变。
- 每次断开后必须重新满足 5 帧张掌条件，不能自动恢复旧零点。

网页“遥操作启用”开关只进入等待离合状态，不直接驱动机械臂。

### 6.2 夹爪

`pinch_ratio` 为拇指尖 4 到食指尖 8 的距离除以食指 MCP 5 到小指 MCP 17 的
掌宽：

- 比值小于 0.32 连续 3 帧：进入关闭状态。
- 比值大于 0.48 连续 3 帧：进入打开状态。
- 中间区域保持上一次状态。
- 只有离合接通且控制手有效时才改变夹爪状态。

打开目标默认 40 mm，可在 0-88 mm 内配置。关闭使用默认 0.15 N·m 限扭矩，
网页允许范围仍为 0.05-0.25 N·m。检测到接触后锁存当前开度，直到明确收到打开
状态；机械臂继续运动时不得重新启动闭合加速。

## 7. 滤波与双档配置

平移使用 One Euro Filter，默认 `min_cutoff=1.5 Hz`、`beta=0.20`、
`d_cutoff=1.0 Hz`。旋转使用基于时间的 quaternion SLERP，默认时间常数 50 ms。
平移目标死区为 2 mm，旋转目标死区为 1.5 度。

单帧浏览器目标变化限制：

- 精细档：平移 5 mm，旋转 3 度。
- 快速档：平移 15 mm，旋转 8 度。

服务端限制始终具有更高优先级：

| 参数 | 精细档 | 快速档 |
|---|---:|---:|
| 平移增益 | 0.5 | 1.0 |
| 旋转增益 | 0.6 | 1.0 |
| TCP 线速度 | 0.03 m/s | 0.10 m/s |
| TCP 角速度 | 0.35 rad/s | 0.80 rad/s |
| 关节速度 | 0.15 rad/s | 0.35 rad/s |

两档都按现有策略同步缩放加速度和跃度，并继续受硬件、反馈与奇异点限制。快速档
不是现有“硬件极速”，不能提升到 SDK 的 5 rad/s 上限。

## 8. WebSocket 协议

遥操作复用现有加密控制 WebSocket，不使用只读视觉桥。消息类型为 `teleop`，动作
为 `start`、`update`、`stop`。

### 8.1 start

离合首次接通时发送：

```json
{
  "type": "teleop",
  "seq": 1,
  "action": "start",
  "params": {
    "profile": "fine",
    "control_side": "right",
    "open_width_mm": 40,
    "closing_torque_nm": 0.15
  }
}
```

服务端仅在控制器空闲、模式允许、安全配置有效且没有其他伺服时接受。服务端保存
当前 TCP、关节和夹爪状态，启动统一伺服，并返回不可预测的 `session_id`。浏览器
启用状态本身不创建服务端运动会话。浏览器收到成功响应后才可发送 `update`；
失败或超时则回到等待离合状态，不使用旧会话继续运动。

### 8.2 update

```json
{
  "type": "teleop",
  "seq": 2,
  "action": "update",
  "session_id": "server-issued-id",
  "client_time_ms": 1780000000000,
  "params": {
    "delta_xyz_m": [0.01, -0.02, 0.0],
    "delta_orientation_xyzw": [0.0, 0.0, 0.1, 0.994987],
    "gripper_state": "open"
  }
}
```

`delta_xyz_m` 和 `delta_orientation_xyzw` 均相对本次 `start`。服务端基于自己保存的
起点计算绝对 TCP 目标，不信任客户端传入绝对机器人姿态。序号必须严格递增；
session 不匹配、字段非有限、quaternion 范数异常或频率超过 60 Hz 时拒绝。

`client_time_ms` 只用于页面遥测。watchdog 使用服务端单调时钟和消息接收时间，
不依赖 Mac 与主机时钟同步。

### 8.3 stop

离合断开、遥操作开关关闭、页面隐藏、切换工具页、摄像头停止或客户端主动退出时
发送 `stop`。服务端即使未收到该消息，也会由 200 ms watchdog 独立停止。

每个响应包含 `seq`、`session_id`、接受状态、错误原因、最新反馈、目标年龄、
安全限制状态和伺服周期指标。浏览器只展示最新序号的响应。

## 9. 服务端统一伺服

新增 `TeleoperationServo`，拥有唯一 100 Hz 工作线程和一组最新目标：

1. 启动时读取反馈、关节限位和安全配置，建立六关节与单轴夹爪 Ruckig 状态。
2. 收到新 generation 时验证相对目标，求解包含目标 quaternion 的 IK。
3. 对短目标段执行安全盒、关节余量、奇异点、自碰撞和配置障碍物检查。
4. 将可接受的关节目标送入在线 Ruckig；拒绝目标时保持上一个有效目标并报告原因。
5. 同一周期推进关节与夹爪规划器，并调用一次 `command_joint_servo()`。
6. 每周期检查反馈时间戳、关节速度、扭矩、夹爪速度、夹爪扭矩和控制模式。

现有 `plan_cartesian_servo_target()` 扩展可选目标 quaternion，保留 gesture 起点和
连续 IK seed。现有鼠标拖动伺服继续使用 XYZ-only 调用，不改变行为。

夹爪关闭时监测电机估算扭矩。达到配置扭矩后平滑制动并锁存当前开度；夹爪接触
不会停止机械臂。夹爪自身超速、反馈停滞或命令异常仍终止整个遥操作会话并进入
故障阻尼。

## 10. 工作空间与安全

遥操作安全配置使用以下保守默认 TCP 安全盒：

```text
base X: 0.15 .. 0.65 m
base Y: -0.35 .. 0.35 m
base Z: 0.08 .. 0.55 m
soft boundary: 0.03 m
```

安全盒由服务端配置，客户端只能读取。配置值必须有限、每轴最小值小于最大值、
软边界小于每轴范围的一半。需要改变工作区时修改受控配置并先走 3D Ghost 验证。

- 当前 TCP 不在安全盒内时拒绝启动遥操作，操作者须先用现有手动控制安全移入。
- 安全盒外目标硬拒绝。
- 距边界 30 mm 内按剩余距离连续降低目标速度，到边界为零。
- IK、关节余量、奇异点、自碰撞和配置障碍物检查继续生效。
- 离合松开、任一必需手丢失或置信度不足时，立即请求 Ruckig 制动并保持当前位置。
- 目标超过 200 ms 未更新时，服务端 watchdog 制动并结束会话。
- WebSocket 断开、页面隐藏或摄像头停止时，结束会话。
- 反馈停滞、超速、超扭矩、模式异常或控制线程异常时立即进入故障阻尼。
- 网页急停和空格急停立即进入阻尼并终止全部运动。
- 普通追踪丢失后须重新接通离合；安全违规或故障后须明确复位或重连。

直接断电可能让机械臂失去保持力并下坠。真机测试时工作区不得有人或易损物，
电源开关须触手可及；软件保护不能替代独立物理急停。

## 11. 界面

### 11.1 控制入口

现有“XYZ 末端 / 单关节”分段控件增加“手势”页签。该页签只切换机器人控制
模式、关闭其他实时伺服并自动打开视觉区的“手势控制”工具卡片；不在机器人
检查器中复制第二套手势控件。

视觉区“手势控制”卡片包含：

- 遥操作启用开关。
- 精细/快速分段控件。
- 左/右控制手分段控件，默认右手。
- 夹爪打开宽度和闭合扭矩。
- Mac 摄像头权限和运行状态。

遥操作启用后显示“等待离合”；离合张掌稳定后显示“跟随中”。不增加单独的执行
按钮，因为离合手本身是持续 deadman 控件。

### 11.2 视觉工具切换

视觉区使用同一工具区域的“手势控制 / 手眼标定”页签，不做卡片嵌套：

- 默认打开手势控制。
- 遥操作开关、双档、控制手和夹爪参数只出现在手势控制卡片。
- 手眼标定页保留安装、采样、验证和启用流程；已有结果显示“已验证”。
- 切到标定页前必须结束遥操作并停稳。
- 标定运行期间禁止切回手势页；取消或完成后恢复切换。
- 两页共用 D455 机器人画面；手势页额外显示 Mac 手部画面并隐藏深度伪彩画面。

### 11.3 可视反馈

- Mac 画面叠加双手关键点；控制手、离合手、捏合状态使用不同颜色。
- 识别无效或追踪丢失时叠加层转为警告状态。
- 3D 机器人区显示实际姿态、半透明实时目标和 TCP 安全盒。
- 状态机显示：未启用、等待离合、跟随、制动、追踪丢失、故障。
- 遥测显示视觉 FPS、推理耗时、WebSocket RTT、目标年龄和服务端伺服状态。
- 现有全局网页急停和空格急停始终可见。

## 12. 最小验收

### 12.1 自动测试

- JS：手势映射、离合、捏合迟滞、quaternion 连续性、滤波和双档限制。
- Python：遥操作协议、安全盒、watchdog、反馈故障和统一机械臂/夹爪伺服。
- 浏览器：遥操作启停、工具页互斥、页面隐藏停止和急停状态。

### 12.2 手动验收

1. Mac 摄像头双手关键点稳定，约 30 FPS。
2. 不连接电机时，3D Ghost 跟手且三个平移轴和三个旋转轴方向正确。
3. 空载精细档小范围真机跟随，无明显抖动、跳变或离合接通位移。
4. 快速档可用；控制手捏合关闭夹爪、松开张开夹爪。
5. 松开离合、遮挡任一必需手、切换页面或断开连接时机械臂停止。
6. TCP 无法越过配置安全盒。

## 13. 分阶段启用

1. Mac 摄像头与双手叠加，只读，不连接机械臂。
2. 记录目标并驱动 3D Ghost，服务端执行全部检查但禁止电机命令。
3. 支撑机械臂、清空工作区，使用精细档和小安全盒真机测试。
4. 验证离合、遮挡、断连和网页急停后启用快速档。
5. 使用柔软物体测试夹爪迟滞、接触停机和限扭矩闭合。
