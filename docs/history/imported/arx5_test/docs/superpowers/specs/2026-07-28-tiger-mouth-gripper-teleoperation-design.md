# 虎口局部坐标系夹爪遥操作设计

- 日期：2026-07-28
- 状态：设计已确认

## 1. 目标

在现有双手手势遥操作中，将控制手的虎口动作映射到夹爪：虎口张开/闭合采用二态控制；虎口平面决定夹爪前伸方向，拇指尖到食指尖方向决定夹爪开合轴；整体运动保持均衡平滑，减少视觉关键点抖动造成的机械臂抖动。

## 2. 坐标与数据流

浏览器继续使用 MediaPipe world landmarks。由控制手关键点建立虎口局部坐标系：

- 开合轴：拇指尖 `4` 到食指尖 `8` 的方向。
- 虎口纵向轴：拇指根 `2` 与食指根 `5` 的中点，指向拇指尖 `4` 与食指尖 `8` 的中点。
- 虎口平面法向：开合轴与正交化后的虎口纵向轴叉积，作为夹爪前伸方向。
- 第三轴：对前两轴正交化并归一化，保证右手、左手采用同一机器人轴约定。

虎口闭合时尖端连线长度变小，开合轴置信度下降。此时保持上一帧有效局部坐标系；若没有上一帧有效姿态，则回退到当前掌面坐标系。关键点非有限、坐标系退化或连续失效超过 watchdog 时，不发送新的运动目标，由服务端停止遥操作。

姿态四元数保持符号连续，并转换到现有操作者到基座的有符号置换矩阵。虎口方向只表达相对姿态，继续以离合接通瞬间的机器人 TCP 姿态为起点，不能改变服务端安全盒、IK、碰撞、速度和 watchdog 约束。

## 3. 夹爪状态机

夹爪不做比例跟随。使用拇指尖 `4` 与食指尖 `8` 的距离除以掌宽作为 `pinch_ratio`：

- 小于关闭阈值连续 3 帧，状态为 `close`。
- 大于打开阈值连续 3 帧，状态为 `open`。
- 阈值之间保持上次状态。
- 只有离合接通且控制手有效时才更新状态；离合断开后重新从安全默认状态开始。

阈值沿用现有配置入口，默认值保持关闭 `0.32`、打开 `0.48`。服务端继续负责开度范围、闭合限扭矩、接触锁存和故障停机。

## 4. 均衡平滑

- 平移继续使用 One Euro Filter，保留 2 mm 死区。
- 虎口姿态使用独立 quaternion 平滑，时间常数约 80 ms，采用最短弧 SLERP。
- 每帧继续限制最大平移步长和最大旋转步长，防止单帧关键点异常造成突跳。
- 虎口局部坐标系只在几何置信度足够时更新；闭合退化或短时丢点保持最近有效姿态，恢复后平滑接管。
- 浏览器帧率、服务端 100 Hz 伺服和服务端速度上限不变，目标是约 80-120 ms 的可接受跟随延迟。

## 5. 实现边界

主要修改集中在 `web/hand_teleoperation_math.mjs`、`web/hand_teleoperation.mjs` 及其 Node/Python 测试。服务端协议字段保持不变，仅消费新的相对姿态目标；不新增绝对深度估计，不绕过现有安全检查，不改变非手势控制路径。

## 6. 验收与测试

自动测试覆盖：虎口二态阈值和迟滞、虎口平面法向与开合轴、左右手一致性、闭合几何退化时方向保持、四元数最短弧和时间戳校验、One Euro/姿态平滑、单帧步长限制，以及现有 WebSocket 和服务端协议回归。

真机验收按低速精细档进行：先验证 Ghost 方向，再空夹爪验证开闭和姿态连续性，最后在无物体风险区验证接触锁存与离合断开停机。网页急停不能替代独立物理急停。
