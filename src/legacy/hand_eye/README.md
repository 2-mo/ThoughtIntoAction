# ARX X5 双相机手眼标定

本目录标定两台 RealSense 的 RGB 光学坐标系外参：

- 眼在手 D405 `230322274781`：输出 `T_eef_camera`；
- 固定外部 D455 `239222300444`：输出 `T_base_camera`。

相机内参使用当前 RealSense 数据流的出厂值。默认标定板为
`DICT_4X4_50 / ID 0 / 100 mm` 单 ArUco。网页入口支持分别或连续自动标定；终端
手动入口保留原有 D455 眼在手外采样能力。

## D405 分辨率与性能

D405 自动标定默认使用原生 **1280×720@30 RGB**，并把实际协商后的内参写入本次会话。
标定检测与浏览器引导画面从同一采集线程取得帧；引导画面只缩放为 **640 宽 / 30 FPS
JPEG**，不会另开 UVC 流、不会参与样本检测，也不会降低标定分辨率。普通 WebRTC 预览
同样以 `1280×720@30` 单源采集，再在媒体轨内缩放为 `640×360@30` 输出；D455 也使用
原生 30 FPS。开始标定时网页会完全释放相机，供标定进程独占。

不连接机械臂的档位探测：

```bash
./arx5 d405-benchmark
```

在关闭网页 D405 视频后，可独占实测旧档位与高分档的采集 FPS、ArUco 检测、缩放 JPEG
耗时和帧间抖动：

```bash
./arx5 d405-benchmark --benchmark
```

`25 FPS` 不是 D405 RGB 的原生请求档位；所有默认相机源与输出都统一为 `30 FPS`。基准
不会连接或驱动机械臂。

## 两种安装状态

两台相机不能在同一种标定板安装状态下同时求解。网页流程依次采集两套数据。

### D405：标定板固定在桌面

D405 随 EEF 运动，标定板在基座坐标系中保持不动：

```text
T_base_eef * T_eef_camera
  = T_base_target * inv(T_camera_target)
```

求解得到 `T_eef_camera` 和本次桌面标定板位姿 `T_base_target`。

### D455：标定板固定在夹爪

D455 固定在环境中，标定板与 EEF 保持刚性关系：

```text
T_base_eef * T_eef_target
  = T_base_camera * T_camera_target
```

求解得到 `T_base_camera` 和本次夹持关系 `T_eef_target`。

两种模式都使用 OpenCV `calibrateRobotWorldHandEye` 的 Shah/Li 方法求解
`A X = Z B`。合成真值测试锁定矩阵方向。D455/D405 的 inverse Brown-Conrady
像素先按 RealSense 模型转为无畸变归一化光线，再执行目标位姿估计。网页可分别
启动 D405、D455，只有“连续标定两相机”才会依次执行两个安装状态。

实现参考 `reference_projects/Bulid_Block/cam_calibration_nero_realsense` 的 17 点
自动运动思路、多帧平均、实测反馈入样本和原始图像留档；本项目另加碰撞预检、
稳定性筛选、双安装状态求解和结果质量诊断。

## 代码分层

```text
hand_eye_calibration/
├── core/          # 相机、目标检测、样本、SE(3)、存储、AX=ZB 求解和指标
├── eye_in_hand/   # D405：固定桌面板的观测方向与结果字段适配
├── eye_to_hand/   # D455：夹爪固定板的观测方向与结果字段适配
├── collector.py   # 组合两种安装流程的机械臂采集编排
└── configs/        # 设备、采样和质量配置
```

`core.solver` 只处理无安装语义的 `A X = Z B`；D405 与 D455 目录分别把 `X/Z`
映射成自己的坐标名称，并独立负责求解结果和留出验证适配。所有共享实现只从
`core` 导入；带安装语义的调用只从对应的 `eye_in_hand` 或 `eye_to_hand` 包导入。

## 环境与标定板

```bash
UV_PROJECT_ENVIRONMENT=.venv-handeye uv sync --only-group handeye
./arx5 calibrate-hand-eye generate-target
```

打印必须使用 100% 实际尺寸，关闭“适合页面”。黑色 marker 外框应为 `100 mm`，
四周白边各 `10 mm`，打印总尺寸 `120 x 120 mm`。纸张需贴在平整硬板上；每个采样
阶段内，硬板与桌面或夹爪的相对位置不能变化。

## 网页自动流程

开始前：

1. 连接机械臂并保持自由阻尼。
2. 把标定板刚性固定在桌面或支架上。
3. 手动摆动机械臂，使 D405 完整看到 marker，并留出运动空间。
4. 清空运动包络，准备实体急停，勾选安全确认后选择“仅标定 D405”、
   “仅标定 D455”或“连续标定两相机”。

随后流程自动执行：

1. 网页停止 D455/D405 视频并释放 `can0`，标定进程独占设备。
2. D405 连续三帧确认起始姿态合格后，自动执行联合平移/旋转的多样化姿态；计划排序
   按预测 EEF 的 6D 运动信息量，而不是按关节变化或单纯旋转排序。
3. 每个独立姿态使用实测 EEF 反馈和 `3 × 20` 帧目标检测 burst 生成一个稳健均值样本；
   同一姿态的重复 burst 用于估计并降低视觉噪声，不能替代新的几何姿态。
4. 每段得到 20 组有效训练姿态后，另采 6 组不参与当前拟合的独立重定位样本；网页显示
   闭环、留一法、Bootstrap 与独立重定位 RMS/P95，并分别显示“拟合 / 独立验证”组数，
   可选择采用或补采 4 组。独立重定位是主指标；Bootstrap P95 只反映设计姿态集在遗漏
   高杠杆视角时的覆盖敏感性。
5. 流程张开夹爪；把同一标定板从桌面移入夹爪，点击“标定板已放入夹爪”。
6. 夹爪先接近到 `7 mm`，再以 `0.30 N*m` 限扭矩夹紧并持续保持。
7. 手动摆到 D455 完整看到 marker 的安全中心，点击“开始 D455 自动采样”。
8. D455 自动执行同类多姿态采样；完成后回该阶段起点。
9. 托住标定板，确认张开夹爪；求解两台相机并恢复网页阻尼连接。

自动计划最多尝试 72 个姿态，以 20 组有效训练姿态为目标。优先使用每点都同时含平移与
旋转的 `20–35 mm` / `8–14 deg` 联合运动，并保留 IK 感知的回退点；不可达、超限或碰撞
预检失败的点不会执行。marker 不可见、机械臂未稳定、重投影或 burst 内抖动超限的样本
会拒绝。误差目标仅用于显示评审警告，不会自动否决已完成的 20 组采样；但样本基础
可观测性仍必须足够，否则不存在可解的手眼变换。

当操作者在评审页选择“纳入评审样本，再采 4 组”时，刚刚完成评估的独立样本会**只在
下一次拟合**中复用，原有训练样本也全部保留；随后从尚未访问的安全端点选择同时改善
最弱 6D 信息方向、且与已有 EEF 位姿距离更大的联合平移/旋转姿态。下一次误差评审必定
使用全新、与拟合端点相隔至少 `1.5°` 的独立验证集，并按评审轮次轻微改变安全视角，
避免把已纳入拟合的样本再次当作验证。这样既不浪费有效观测，也不会把重定位误差报得
过于乐观；不按 Bootstrap P95 反向删除样本。

普通取消会返回当前阶段起始姿态；若标定板在夹爪中，会等待人工托住后再张开夹爪。
急停、网页断开或进程异常立即进入阻尼，不执行自动返回。

## 终端手动 D455 采集

终端 `capture` 仍是单相机 D455 眼在手外模式：标定板固定在夹爪，人工改变姿态并
按键采样。运行前必须停止网页服务，释放 D455 和 `can0`。

```bash
./arx5 can-up
./arx5 calibrate-hand-eye capture --confirm-safe
```

- `Space` / `S`：采样当前稳定姿态；
- `D`：删除最后一组；
- `Q` / `Esc`：结束并求解。

## 输出、复算与启用

每次会话位于：

```text
outputs/calibrations/hand-eye/eye-to-hand/sessions/YYYYMMDD-HHMMSS/
```

双相机 `samples.json` 按 `eye_in_hand`、`eye_to_hand` 保存两套样本和两台相机内参；
图像使用 `d405_`、`d455_` 前缀。`result.json` 包含：

- 顶层 `T_eef_camera`、`T_base_camera`；
- `eye_in_hand`、`eye_to_hand` 两套完整残差、剔除样本和留一法稳定度；
- 顶层 `T_base_camera` 继续兼容现有 D455 小方块定位消费者。

最近结果同步到 `current.json`。离线复算不连接硬件：

```bash
./arx5 calibrate-hand-eye solve --session YYYYMMDD-HHMMSS
```

网页“验证缓存结果”会分别检查两套数据：至少 12 组、闭环平移 RMS 不超过 `5 mm`、
最大不超过 `10 mm`、旋转 RMS 不超过 `2 deg`、最大不超过 `3 deg`，并验证
`T_eef_camera` 与 `T_base_camera` 都是合法 SE(3)。这些数值是质量建议，不会在自动
采集阶段阻塞；两阶段各完成 20 组并在评审页明确采用后，网页可再次确认人工采用该
结果。样本数和 SE(3) 合法性仍不可覆盖。停用不会删除样本或求解结果。
